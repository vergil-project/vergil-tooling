    Release 2.1.334 (2026-11-22)¶

    Bug fixes¶

    • restore the cast import that the merge of #4879 and #4880 dropped (#4883)
    • order open releases by semantic version, not as strings (#4885) The fresh-start open-release refusal and the --resume ambiguity message sorted release versions as strings, listing 2.0.10 before 2.0.9. Both now sort with the existing host_versions.compare comparator. Ref #4877
    • refuse a resume whose release branch is missing (#4888)
    • fix(release): refuse a resume whose release branch is missing

    A resume that adopts the release worktree now refuses, naming release/, when that branch exists neither locally nor on origin, instead of cutting a new branch from develop. A fresh run still creates the branch off develop. Ref #4886.

    • style(release): format the missing-branch resume test

    • let a resume past merge-release run without the deleted release branch (#4892)

    • fix(release): let a resume past merge-release run without the deleted release branch

    Once the release PR merges, GitHub deletes release/, so a resume whose first undone stage is confirm-main, back-merge-bump or teardown-worktree no longer adopts the branch. It reuses the release worktree if it is still there (refusing a path that is not a git worktree), creates one detached at develop when back-merge-bump still has to run, and otherwise runs from the root checkout, where teardown-worktree does nothing and is recorded done. The #4886 refusal stays for prepare and merge-release. Ref #4889

    • fix(release): format the post-merge tests and flatten the resume worktree bullets

    • record the release's target version bump so a resume never drops it (#4909) The state block records version_bump, the bump prepare applies to reach the target version, at the tracking issue's creation. A resume before merge-release holds the release branch's committed VERSION to the target: it completes a bump prepare stopped before, and refuses any other VERSION or an uncommitted version change, naming both versions. prepare refuses a bump that misses the target and an existing release PR while the bump is pending. Ref #4899.

    Features¶

    • keep the release state in the tracking-issue body (#4876)

    • feat(release): keep the release state in the tracking-issue body

    • fix(release): clear lint, type and coverage findings in the state block

    • fix(release): address merge-review findings R1 and R2

    • lock the tracking issue and trust only human state changes (#4879) prepare locks the tracking issue it creates, and every read of the state block (read_state, and write_state's own read) first locks an unlocked issue and then applies the identity rule from the new lib/release/guard.py: a non-human author, body editor, or close or reopen actor is a suspected security breach that stops the run before any write, and other foreign traces are warnings printed once per run. Task 3b of epic vergil-project/.github#1440. Ref #4847

    • refuse a fresh release while any release is open (#4880) A fresh vrg-release now refuses while any release: X.Y.Z tracking issue is open, not only one for its own version, naming each open issue with vrg-release --resume X.Y.Z, or, for an issue with no state block, the old-tooling recovery. The open-release lookup is shared with --resume and now raises on a malformed response instead of reading it as no release. The version-specific lookup it replaces is removed. Task 5 of vergil-project/.github#1440 (spec 4.7). Ref #4849
    • list the issues a release closes (#4881)
    • feat(release): list the issues a release closes

    Preflight reads the trusted closing references of the release's feature/ PRs in the pending-release GraphQL queries, prints the Contents table and issue list, and stores the list on the context for the tracking issue (Task 6 of epic vergil-project/.github#1440).

    • refactor(release): name the closing-reference check counted_closing_refs

    • refactor(release): keep trusted_closing_refs as the plan's public helper

    • style(release): sort the pending-release test imports

    • resume from the first undone stage (#4884)

    • feat(release): resume from the first undone stage

    Each tracked stage records itself done in the tracking issue's state block, with the PRs, tag and CD runs later stages need; --resume reads the block under the identity rule, verifies its facts against GitHub and git, and runs only the stages not recorded done. teardown-worktree is fail-fast, and a resume adopts the release worktree only when its first undone stage is at or before it. Ref vergil-project/vergil-tooling#4848.

    • docs(release): match the resume guide to what publish-status and consumer-refresh do

    Merge review R1 and R2 on #4848: the publish-status error no longer names the pending promote, and a consumer-refresh with no commands configured is recorded done; only one that was held back runs again on a resume.

    • test(release): stub the tag peel in the confirm-main retry test

    _verify_artifacts now records tag_commit with git rev-parse; the 404-retry test left it unpatched, so it read the real repo's tags and failed in CI, where v2.1.0 is not fetched.

    • make the index wait and the dependency update resumable (#4890)
    • feat(release): make the index wait and the dependency update resumable

    On --resume, package-index dispatches the publish-index workflow itself (unless the index already lists the release) and follows only the run it started; a listed release is recorded as index_listed. --without-deps given on a resume is recorded in the state block, and a recorded skip carries across every later resume. Ref #4852.

    • fixup! feat(release): make the index wait and the dependency update resumable

    • docs(release): say a failed update-deps resumes only while the tracking issue is open

    • deliver failed CD publish jobs on resume (#4891)

    • feat(release): deliver failed CD publish jobs on resume

    confirm-main and confirm-develop record each failed CD publish job in the state block (run ID and full job name); a new cd-publish stage defers them on a fresh run and delivers them on --resume. A failed CD release job is recorded as failed_release_run and recovered inside confirm-main on resume (CI re-run, then CD re-run), replacing the hand-run steps. deferred_publish_failures becomes a view of the state block. Task 7a of epic vergil-project/.github#1440 (#4851).

    • test(release): cover cd-publish's edge cases and type its run matcher

    • test(release): list cd-publish among the stages before update-deps

    The update-deps resume test from #4890 lists the stages done before update-deps; cd-publish now runs between confirm-develop and package-index. Ref #4851.

    • decouple promote and install from packaging and rename the install (#4894)
    • feat(release): decouple promote and install from packaging and rename the install

    Task 8 of epic vergil-project/.github#1440 (vergil-project/vergil-tooling#4853). promote moves vX.Y once the tag and Release exist; finalize runs only vrg-finalize-pr --cleanup-only and a new close-tracking stage closes the tracking issue last; the hold rule (handoff.holds) replaces OPTIONAL_STAGES and blocking_failures; consumer-refresh becomes the install stage, gated on promote and on vX.Y naming the release, with and the [publish].install key (consumer-refresh read with a deprecation warning); the hand-run remedy messages go.

    • fix(release): hold cd-publish until confirm-develop succeeds

    Merge review R1 on vergil-project/vergil-tooling#4853: run past a failed confirm-develop, cd-publish found nothing recorded and was recorded done, so a resumed confirm-develop's failed job was never delivered and close-tracking could close the issue.

    • remove vrg-release --no-promote and --no-install (#4895)
    • feat(release): remove vrg-release --no-promote and --no-install

    Promote and install are part of every release (spec §4.8 of epic vergil-project/.github#1440). Both flags, like --install before them, are still parsed and hidden from --help, only to exit 1 before any side effect with a removal message. The opt-out paths behind them go too: ReleaseState and ReleaseContext lose promote and install, the orchestrator loses _opted_out and the promote skip, and the install stage always runs the configured commands. The reference, the releasing guide (rollback section included) and the CLI overview are updated. Ref vergil-project/vergil-tooling#4854

    • feat(release): keep main first in vrg-release and format the update-deps tests

    Ref vergil-project/vergil-tooling#4854

    • docs(release): drop --no-install from the releasing guide's install row

    Ref vergil-project/vergil-tooling#4854

    • post a Released: record on every issue a release contains (#4896)
    • remove the submit and finalize opt-outs (#4897) vrg-submit-pr --no-finalize and --no-install and vrg-finalize-pr --no-install are still parsed, hidden from --help, only to exit 1 before any side effect with a removal message (spec §4.8 of epic vergil-project/.github#1440): submit always finishes, returning once each PR has merged or cannot merge, and install is part of every release. The --no-finalize paths (the pr-watch lines, the not-watching hint, skipping an already-submitted relay branch) and the --no-install pass-through go with them. The submit and finalize references, the git-workflow guide, the CLI overview and the permission-model spec's accepted gap are updated. Ref vergil-project/vergil-tooling#4855
    • supersede a release that cannot finish (#4898)
    • feat(release): supersede a release that cannot finish

    Adds vrg-release --supersede X.Y.Z (spec 4.7 of epic vergil-project/.github#1440): eligibility, absorbing the superseded release's issues, closing its tracking issue, the untagged path's next patch and main-ahead acceptance, and the Supersedes: line on absorbed issues' records. Ref #4857

    • test(release): cover the supersede refusals and the branch removal

    • docs(release): name the usage-error exit code of vrg-release

    • fix(release): close the superseded issue only once the release PR exists

    • fixup! fix(release): close the superseded issue only once the release PR exists

    • supersede a release whose tracking issue fails the identity rule (#4910)

    • feat(release): supersede a release whose tracking issue fails the identity rule

    A breached tracking issue can never pass the identity rule again, so --supersede no longer reads its state block: it rebuilds the release from GitHub and git facts (its merged release PR, its tag and GitHub Release or its failed CD release job, its back-merge, and its issue list, including issues absorbed from a release it superseded). The breach message and the releasing guide now point at this recovery instead of cleaning up and resuming. Ref #4878

    • test(release): cover the breached-release rebuild in full

    • add vrg-release-record check and use it in the deployment scaffold (#4933)

    • feat(release): add vrg-release-record check

    • fixup! feat(release): add vrg-release-record check

    • fix(release): count type-filtered timeline items by filteredCount

    GitHub's totalCount on a timelineItems connection with an itemTypes filter counts every timeline item, so the completeness check refused almost every real PR. The closing-reference trust check and the tracking-issue guard now read filteredCount.

    • fixup! fix(release): count type-filtered timeline items by filteredCount

    • fixup! feat(release): add vrg-release-record check

    • fixup! fix(release): count type-filtered timeline items by filteredCount
