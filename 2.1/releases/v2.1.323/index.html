    Release 2.1.323 (2026-11-18)¶

    Bug fixes¶

    • refuse an --all-in sweep when the identity may not see every repo in the org (#4646)
    • fix(adhoc-epic): refuse an --all-in sweep when the identity may not see every repo in the org

    vrg-adhoc-epic archive/normalize --all-in walk the org's repos, private self-homed ones included, through list_org_repos, which lists only what the token can see. A token without full coverage read as 'no private homes'. Both now run epic_audit.coverage_gap first (the #3513 signal vrg-epic-audit already uses) and exit 1 before any read when coverage is in doubt. Ref #4579.

    • style(adhoc-epic): format the --all-in coverage guard

    • say an unfinished ancestor CD run is not finished, not timed out after 0s (#4655) The develop-CD gate judges an ancestor run with no wait, so the timed-out refusal reported a wait that never ran. Each caller of _judge_run now words its own unfinished-run refusal; the head-run message is unchanged.

    • keep --allow-provenance-violation from releasing past a merged violation (#4665) The override now covers only an open PR's auto-merge. A PR that merged with a provenance violation blocks full success and any chained release, with or without the flag (exit 3, or 4 when develop did not validate). Ref vergil-project/vergil-tooling#4662.

    Build¶

    • raise vergil-tooling's floor to Python 3.15 (#4647)
    • build(python): raise the Python floor to 3.15

    requires-python becomes >=3.15, ruff targets py315 and mypy checks as 3.15; uv.lock is re-locked, dropping the pre-3.15 resolution markers and wheels. The ruff UP pass rewrote two datetime.timezone.utc uses in scripts/perf to datetime.UTC; the import lines were then tidied by hand, since ruff left timezone imported but unused. Ref vergil-project/vergil-tooling#4608

    • test(python): rename test locals that shadow Python 3.15's sentinel builtin

    Python 3.15 adds a sentinel builtin (PEP 661), so with ruff targeting py315 the flake8-builtins rules A001/A002 flag seven test locals and parameters named sentinel. They become expected_gates, fake_ctx and epic_sentinel. Ref vergil-project/vergil-tooling#4608

    • style(python): drop the parentheses from multi-exception except clauses

    ruff format at target py315 writes PEP 758's parenthesis-free form (Python 3.14+) for an except clause naming several exceptions with no 'as' binding. Behaviour is unchanged. Ref vergil-project/vergil-tooling#4608

    • build(ci): pin the CI versions to Python 3.15

    The version resolver ignores requires-python, so the floor raise alone left 3.12-3.14 in the CI matrix and vrg-validate --all-versions, where uv sync fails. Pin [ci].versions to the floor until vergil-project/vergil-tooling#4639 makes the resolver honour it.

    • build(ci): resolve vergil-tooling as a tooling repo instead of pinning 3.15

    Every install path now runs vergil-tooling on its own Python 3.15 interpreter, so no consumer runs it on a window version it builds and the reason it was a library is gone. As a tooling repo it resolves as an app and builds the newest window version with a published runtime, which replaces the [ci].versions pin. Updates the docs that described it as a library covering 3.12 to 3.15. Per the merge-review ruling on R1. Ref #4608

    Chores¶

    • uv lock --upgrade
    • lint-clean scripts/perf/ under the repo's ruff configuration (#4656) Fixes every ruff finding in scripts/perf/ without suppressions: ruff format wraps the over-long lines (E501), the defusedxml import drops the ET acronym (N817) and the import block is sorted (I001). The bare "uv" subprocess calls (S607) now resolve uv through shutil.which, failing loudly with a clear message when it is not on PATH.

    Documentation¶

    • name Python 3.15 in the remaining install docs and drop the stale CI example (#4653) The documentation review for epic vergil-project/.github#1256. The README's CI example checked out v1.2 and synced with no --python; it now points at the shared/setup/vergil action the reusable workflows already run. The cache-image, VM dev-install and releasing pages now name --python 3.15 for the git installs the code runs that way, the evidence-convention page no longer lists 3.12 to 3.14 as this repo's versions, and the version-management page says the floor does not choose the versions vergil-tooling builds and what happens when a newer series joins the window. Ref #4578
    • supersede the up-to-date rationale; update the provenance mitigation (#4667)

    Features¶

    • serialize local develop sync and cleanup with a checkout lock (#4641) Add lib/checkout_lock.py, an exclusive fcntl.flock on build/.vergil-state/checkout.lock that records its holder, waits loudly and refuses nesting. vrg-finalize-pr --cleanup-only holds it from cleanup through validation and lets go before the CD check; vrg-release's update-deps stage holds it for its fast-forward. Task 8 of epic vergil-project/.github#1218 (#4566).
    • add batch-check for a submitted batch PR (#4642)
    • feat(pr-workflow): add batch-check for a submitted batch PR

    vrg-pr-workflow batch-check --pr [--head ] checks a submitted batch PR before a push to it: its body's Closes refs against GitHub's closing references, and one commit per issue from the PR's base to the head. The closing-reference check moves out of vrg-finalize-pr into batch_rules.check_closing_refs, which finalize's merge path now calls. Ref vergil-project/vergil-tooling#4570

    • fixup! feat(pr-workflow): add batch-check for a submitted batch PR

    • open every PR through one path with auto-merge on (#4643) Template, CLI, worktree-batch and named-branch modes now gate and preview their PRs, ask one confirmation, and open them through one _submit_all loop: push, hold origin to the recorded head, open the PR, record it, run the provenance check, then turn auto-merge on pinned to that head (rebase for a batch PR, squash otherwise). A failed PR is named in the summary and the rest continue. Submit no longer rebases a batch, so the rebase helper and its merge-commit refusal are removed, and any base other than develop is refused. Adds --allow-provenance-violation. Ref vergil-project/vergil-tooling#4574

    • fast-forward develop in preflight instead of refusing (#4650) Release preflight now takes the checkout lock, refuses a dirty tree or a diverged develop, and fast-forwards a develop that is behind origin/develop before the develop-CD gate checks the new head. When vrg-release runs update-deps, its preflight fast-forwards the same way under the lock; run standalone it is unchanged. Task 9 of epic vergil-project/.github#1218 (#4567).
    • report develop CD instead of waiting; --wait-cd opts in (#4651)
    • feat(finalize): report develop CD instead of waiting; --wait-cd opts in

    By default the cd-check stage now finds the CD run for the synced head and prints 'CD: ' without waiting (or 'CD: no CD run for this head'). --wait-cd restores the blocking watch and judges a failed run's jobs with cd_runs.classify_jobs, so a docs-only failure is a warning, as in the release gate. --no-wait-cd is refused with exit 1, and vrg-release's cleanup call drops it. A batch passes --wait-cd through to its end-of-batch cleanup-only run. Task 12c of epic vergil-project/.github#1218.

    • fixup! feat(finalize): report develop CD instead of waiting; --wait-cd opts in

    • feat(finalize): report a repo with no CD workflow without a warning

    • style(finalize): use the Python 3.15 unparenthesised except form ruff format now requires

    • wait for the PR to merge: exit 0 merged, 1 cannot merge, 2 other errors (#4654)

    • feat(pr-await): wait for the PR to merge: exit 0 merged, 1 cannot merge, 2 other errors

    vrg-pr-await now waits on a PR submitted with auto-merge until it merges (exit 0, with the merge commit) or can no longer merge as it stands (exit 1, with a named reason: check_failed, conflict, auto_merge_off, closed, orphaned_check or timed_out). Any other error exits 2. Reviews and new commits no longer end the wait. The deadline is $VRG_FINALIZE_DEADLINE, checked before any read. It reads the PR through finalize_watch's snapshot and required-check judgement, now public, and the snapshot gains the merge commit. PrMergedError, the --since-sha/--since-reviews baselines (now fatal errors) and the unused github.pr_reviews are removed. Ref vergil-project/vergil-tooling#4648

    • fixup! feat(pr-await): wait for the PR to merge: exit 0 merged, 1 cannot merge, 2 other errors

    • fix(pr-await): keep the permission and missing-token guidance on the PR read

    finalize_watch.snapshot wraps gh failures in FinalizeWatchError; vrg-pr-await now routes a wrapped GitHubAPIError through the same missing-token, permission and API-error messages. Merge review R1. Ref vergil-project/vergil-tooling#4648

    • finalize watches a batch, then settles develop once (#4660)

    • feat(finalize): finalize watches a batch, then settles develop once

    • test(finalize): cover the settle report's edge paths

    • fix(finalize): name CD in a --wait-cd failure report; tail each validate stream apart

    • finalize by default; --no-finalize opts out (#4666) vrg-submit-pr now runs one vrg-finalize-pr over every PR it opened, passing --release, --no-install and --allow-provenance-violation through, and drops --release after a failed submit. Its exit status follows finalize's with a failed submit at least 3 and a finalize tool error always winning. --no-finalize opens the PRs and prints the finalize command. The interim cascade is gone: submit's --finalize and --install and finalize's --skip-post-checks and --install are fatal, and lib/pr_workflow/batch.py, the serial per-PR loop, is removed with its last caller. Refs #4575.

    Refactoring¶

    • remove the cutover install switch from the cache build (#4664)

    • refactor(container): remove the cutover install switch from the cache build

    • style(container): wrap the rewritten order-marker assertions to the line limit
