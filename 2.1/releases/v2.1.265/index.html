    Release 2.1.265 (2026-10-25)¶

    Bug fixes¶

    • give per-kind advice for deferred publishes (#3561) The deferral comment and the close-finalize message treated every deferred publish as a CD job. A deferred package-index now gets advice to re-run (or wait for) the publish-index workflow in the org's packages repo, resolved from [package].vendor, and to confirm the release's packages appear in the index. CD jobs keep their advice, both are given when both kinds are deferred, and the do-not-resume warning stays (#3543).

    • remove the retired triage/idea/research labels and have the sync delete them (#3564) Drop the three retired intake kind labels from data/labels.json, and make vrg-ensure-label --sync delete them (alongside the registry's delete list) from any repo that still has them. The retired names come from intake_route.RETIRED_LABELS, the single source of truth. Deletion lists the repo's labels first and deletes only those present, so it is idempotent and reports each removal, and a real gh error now propagates instead of being swallowed. Ref #3546

    • audit TypeScript devDependencies, not just production (#3567) The TypeScript AUDIT step drops --omit=dev, so npm audit checks every package in package-lock.json, devDependencies included. A vulnerable docs or test tool now fails the gate. The license summary stays production-only. Refs #3552

    • replace and verify the parent after a cross-repo one-off transfer (#3569) A transfer carries the intake parent across, sometimes only after a delay, so the post-transfer link either failed (Sub issue may only have one parent) or was silently overwritten. The transfer path now links with replaceParent, waits, re-reads the native parent and replaces it again if it reverted, failing loudly with a vrg-epic-move fix after bounded rounds. The recreate path links and verifies once. Ref #3556

    • resolve a bare --epic #N against the current repo's epic home (#3572) vrg-epic-audit --epic parsed a bare #N against the cwd repo, so from a public code repo it looked up the wrong issue. Qualify it with epics.qualify_epic_ref against the current repo, giving /.github#N for a public repo and the repo itself for a self-homed private one. The visibility probe runs under the current repo owner's App token. A full owner/repo#N is used as written, with no lookup. Ref #3415

    • re-poll suspected orphaned check-runs for a grace period before failing (#3574) During a GitHub Actions incident, job results are written back late, which looks identical to an orphaned check-run at the moment of checking. The check waiter (vrg-finalize-pr, vrg-release) and vrg-pr-await declared an orphan after one minute or immediately, advising a close/reopen that discarded results already on their way.

    A check pending over a completed run is now a suspected orphan, re-polled (job re-read every 30s) for VRG_ORPHAN_GRACE seconds (default 300) with a warning naming the suspects. A result arriving in the window finishes the wait normally; only an expired suspect raises OrphanedCheckError, naming how long each check waited.

    • retry an empty head-SHA run lookup before failing the evidence gate (#3575) GitHub's run-by-SHA index can trail a just-completed CI run, which failed the vergil-containers 2.1.30 release gate although the run existed. harvest now re-queries an empty lookup with backoff for a bounded grace period (--run-grace-secs, default 300s, inside the step's 15-min timeout), logging each retry, then fails with a message naming the wait. A visible failed or in-progress run still fails at once. Ref #3434

    • stage docs sources like CI before mkdocs runs (#3576) vrg-container-docs now runs vrg-docs-stage and vrg-docs-patch-nav on the host before mkdocs, matching CI's docs staging, so local strict builds pass or fail where CI does. The nav patch goes to a gitignored sibling copy (mkdocs.staged.yml); the tracked mkdocs.yml is never rewritten. The generated paths are added to the managed base gitignore, and the command refuses before writing when any generated path is not ignored (e.g. a committed staged copy). Missing gh auth fails the command; staging is never skipped. Adds git.is_ignored (check-ignore). Ref #3439

    • add vrg-container-cache prune for finished-branch cache images (#3577)

    • fix(container-cache): add vrg-container-cache prune for finished-branch cache images

    Cached per-branch images piled up on agent VMs because vrg-finalize-pr only cleans the machine it runs on (#3481). The new prune subcommand keeps an image whose sanitized branch matches a live branch (local, worktree or origin) in any repo of the repo set, removes the rest, and never touches protected branches or images a container uses. Dry run by default; --apply removes and fails loudly on rmi errors. The multi-repo live-branch lookup lives in lib/live_branches.py for reuse by #3566.

    • fix(container-cache): fall back to tracking refs when a repo's origin is unreadable

    On a Lima VM the default repo set is the whole mounted projects tree, which includes private repos the agent's App cannot ls-remote, so one unreadable origin aborted every prune. Such a repo now contributes its local refs/remotes/origin/* instead, with a warning naming the repo and the error. Tracking refs are stale only toward listing deleted branches, so the fallback keeps more, never less. Any other git failure still stops the run.

    • test(container-cache): wrap long prune test signatures for lint and ty

    • ensure the in-progress label in a planning item's own repo (#3578) ensure_planning_epic ensured 'in-progress' only in the planning queue home, so a member-repo item moved into planning could not be labelled by epic-create ('in-progress' not found). It now also ensures the label in the target (item) repo, deduplicated when the two coincide. Every entry into planning (the planning sentinel in vrg-epic-move and vrg-issue-create, and vrg-intake-route planning) already passes the item's repo here, so this one change covers all three. Ref #3520

    • record relay submissions on the local worktree (#3579) A branch submitted by name that is already on origin went down the relay path, which opened the PR but never recorded it. When that branch also had a local ready worktree, its state stayed ready with no submission, so the freeze refused pr-watch fix commits and pushes. Record the submission on the local worktree after any successful live open; branches without a local worktree are unchanged. Ref #3525

    • preflight refuses on main/develop divergence with a recovery path (#3580) A fresh vrg-release now fetches main and refuses before anything is cut when origin/main has commits not on origin/develop, naming the commits and the recovery: vrg-release --resume for a release stopped before its back-merge, else a manual back-merge PR merged with a merge commit. Develop ahead of main stays normal; a resume skips the check; a failed fetch or compare refuses. Ref #3527

    • preview the real per-repo verdict in a sweep dry run (#3585) In dry-run mode run_sweep now runs each applicator check-only in a disposable detached probe worktree and reports the verdict a live run would reach (ready, skipped, or a follow-up) instead of reporting every repo ready. The Applicator seam gains a check keyword: the xdist and ci.yml applicators compute the verdict without writing (xdist runs no uv lock), the dependabot target previews with vrg-dependabot-sync --check, and the gitignore target runs --write inside the discarded probe because vrg-gitignore-sync --check is stricter than --write. The xdist sweep also treats a repo that is not a Python repo as out of scope, so it no longer files follow-up issues against docs or container repos. Ref #3549

    • file a fix task when an updater or hook fails (#3586) An update-kind failure (an updater or the repo hook failing before validation) opened no PR and filed no fix task, so it was recorded only in run output and the release tracking comment. fix_task_stage now files a fix task for every failure. For an update failure the task stands on its own: it names the failing updater (recorded on DepsFailure.updater), carries the error and output, and says how to reproduce it on develop and where to cut the fix branch. failure_summary names the fix task for update failures too, and failure_markdown no longer tells the reader to reproduce on a branch that was never pushed. Docs updated to match. Ref #3550

    • scan the C++ conan audit in the lock's Debug configuration (#3587) conan audit scan already covers test_requires and tool_requires (every non-root graph node, both contexts) and implicitly loads conan.lock, but it resolved the default Release profile, so locked packages a recipe requires only in Debug (the build_type conan lock create and INSTALL use) were never scanned. Pin -s build_type=Debug and pass --lockfile=conan.lock explicitly on both AUDIT conan steps so the scan matches the lock and a missing lock fails instead of re-resolving. Verified against Conan 2.33 with a test recipe.

    • give the human exact commands to resolve a submitted PR's merge conflict (#3589) A conflict on an already-submitted PR can only be resolved by the human: the branch is frozen to agents. vrg-finalize-pr now replaces the generic advice with the worktree path (or how to create one), fetch, merge of the base branch (not a rebase, since the PR is public), validation, raw-git commit and push, and the re-run. pr_merge raises a MergeConflictError subclass so other callers are unaffected. Ref #3555.

    • defer a package-index miss before close-finalize so the tracking issue stays open (#3596) Move the package-index stage ahead of close-finalize so an index-only timeout reaches the deferral comment and leaves the tracking issue open, as a CD publish deferral does. A stage that records its own failure as a publish deferral is no longer added to the halted-stage list, so close-finalize does not mistake it for a resumable failure. The publish-status and consumer-refresh hold messages now use publish_deferred_remedy for per-kind advice. Ref #3557.

    • comment on the open fix task instead of filing a duplicate on a re-run (#3597) Before filing a fix task, look for an open one with the same version-keyed title and the same failure kind (its '## Failure: ' heading). If one exists, add the new failure to it as a comment and link that task from the PR body and run summary. A failed or malformed lookup fails loud rather than risk a duplicate. Ref #3560.

    • run the image's mkdocs when a Python repo has no docs dependency group (#3598) vrg-container-docs ran 'uv sync --group docs' for every repo with a pyproject.toml, so a repo with no docs group (vergil-tooling itself) failed with uv's 'Group docs is not defined'. CI's docs jobs sync no group: they run 'uv run mkdocs', which falls through to the docs image's mkdocs-material. Match that: sync the docs group only when pyproject.toml declares one, otherwise run plain 'uv run mkdocs' and print a note saying the image's mkdocs is used. An unparseable pyproject.toml now fails with a clear error before the container starts.

    • keep other repos' branch images in finalize's prune; report rmi failures (#3599) vrg-finalize-pr's orphan-image sweep now asks the platform repo set (the same live-branch lookup and plan_prune verdicts as vrg-container-cache prune) instead of the finalized repo's local branches, so it no longer deletes other repos' in-progress images. It is skipped, with a message, where no repo set can be confirmed (the physical host), and a failed lookup or rmi is a warning, never a failed finalize. clean_branch_images and the sweep move to lib/cache_prune.py and return their rmi failures; vrg-container-cache clean and clean-all name each failed image with the runtime's error and exit 1. Ref #3566

    • make vrg-gitignore-sync --check and --write agree (#3600)

    • fix(gitignore): make vrg-gitignore-sync --check drift exactly when --write would change the file

    --write now removes exact repeats of the fence's own patterns outside the fence (the fence is the single source of truth), and --check now flags a fence that is not first, a missing trailing newline, and any other layout --write would rewrite. --write then --check always passes. Ref #3568.

    • fix(fleet-sync): preview the gitignore target with vrg-gitignore-sync --check

    With --check and --write consistent, the gitignore dry run no longer needs to write inside the probe worktree; drop check_predicts_write. Ref #3568.

    • self-heal a conflicting release PR by merging main into it (#3601) When the release PR is CONFLICTING, merge-release now merges origin/main into the release branch in its worktree and pushes it, then waits again (bounded to 3 attempts). A conflict in CHANGELOG.md alone is resolved by keeping the release branch's generated changelog; any other conflicted path aborts the merge and stops with the exact commands to resolve it by hand. Re-runs are idempotent: an already-merged main is not merged again, and a local merge a prior run did not push is pushed. Refs #3526.

    • say whether close-finalize closed the tracking issue or left it open (#3609) The close-finalize completion comment always read 'Tracking issue closed. Repository finalized.', even when a deferred publish (CD jobs or package-index) or a halted earlier stage left the issue open. It now mirrors close_and_finalize's branches and names each deferred kind. Ref #3593

    • skip gitignored files in the common lint checks (#3610) vrg-container-docs build copies the gitignored release notes and changelog into docs/site/docs/, and the common markdownlint check then linted them, failing the next vrg-validate until they were deleted by hand. Every file list the common checks discover (markdownlint, shellcheck, yamllint, hadolint) now drops the paths the repo's .gitignore excludes, via a new batched git.ignored_paths (one git check-ignore --stdin call). Tracked files are always kept, and a check-ignore failure raises rather than linting less. Ref #3594

    • self-home a private repo whose owner has no .github (#3614) resolve_epic_home crashed with a traceback for a personal-account repo with no /.github: the .github visibility probe failed with 'Could not resolve to a Repository'. A private repo whose owner has no .github now homes its epics in itself (there is no central home). Only GitHub's not-found answer counts as absent; every other probe failure raises EpicHomeError, which cli_main prints as a one-line ': ' instead of a traceback. A missing token keeps its own error. The not-found classification is factored out of repo_exists as github.is_repo_not_found. Docs record the new row of the epic-home rule.

    • fail validation cleanly when the image rebuild fails (#3616)

    • fix(finalize-pr): report a failed cache re-provision as a warning instead of a stage failure

    When validation's container fails to launch, finalize rebuilds the dev image and retries. A failed rebuild (the low-disk guard refusing it, a failed cache build or commit, or an unresolvable version window) now prints a warning naming the image, the full error text and the retry command, marks the validation stage warn, and skips the retry, instead of failing the stage with a raw exception after the merge has landed. Ref #3605

    • fix(finalize-pr): fail validation when the dev-image rebuild fails

    An unrun validation is an unknown result, not a pass (#3316).
