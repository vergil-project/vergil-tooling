    Release 2.1.339 (2026-11-23)¶

    Bug fixes¶

    • treat the checked repo's own docs site as published in docs-links (#4612) A new repo's generated README links to its own docs site, which the fixed site lists cannot name until a vergil-tooling release adds it, so the repo failed docs-links from its first PR. The check now treats the repo's own site as a published, versioned site when [publish].docs is true and origin is a vergil-project repo on GitHub.
    • report an unparsable package.json once in the TypeScript pre-gate (#5020) The Prettier single-source check wrapped the package.json parse error in its own prefix, so the pre-gate's de-duplication missed it and listed the error twice. It now reports the error in the same words as the other checks, so it appears once.
    • report cached images prune cannot place instead of keeping them silently (#5000) Prune kept every protected-branch cache whatever its repository, so caches of repositories that no longer exist piled up unseen. A protected-branch image whose repository is in no repo of the scanned roots is now marked unplaced: prune still keeps it, since the repository may live outside the roots, but lists it with the command to remove it by hand.
    • verify earlier steps' capture records when building a check request (#4614) vrg-merge-review-request re-checked each earlier result with parse_result but not its capture record, so a result edited after its own step's check passed there. It now runs check_capture (rule 10) first, as vrg-merge-review-check does.
    • report an unlabelled Security advisory: line on an untracked issue (#4996) vrg-epic-audit now checks every open issue in the audit's one enumeration for a Security advisory: line on a trusted body without the security label, and reports each as a broken pair in the security-records preview, by issue ref alone, whether or not an advisory tracks it (spec 6.3 of vergil-project/.github#1331).
    • fail the C/C++ dependency audit when the Conan token is missing (#4999) vrg-validate no longer drops conan audit scan when CONAN_AUDIT_PROVIDER_TOKEN_CONANCENTER is unset or blank. The scan is not run, an error names the token, and the AUDIT stage fails while its other commands still run, so a missing token is never a silent pass.
    • fail report-ready when the relay ref is not written (#5051)

    • fix(pr-workflow): fail report-ready when the relay ref is not written

    • style(pr-workflow): wrap the report-ready module docstring to the line limit

    • stop swallowing version-file errors in bump() and bump_paths() (#4588) A Go repo with no version.go is now an explicit None from _discover_version_file rather than a caught FileNotFoundError, so bump(), bump_paths() and show()'s cross-check need no (FileNotFoundError, ValueError) handler. A version file that exists but cannot be read or written now fails with a VersionSyncError naming the file and the fix, and bump() restores every saved path.

    • report a malformed version file in vrg-version show in one line (#5019) pyproject.toml, version.go, a Cargo.toml that is not valid TOML and .claude-plugin/plugin.json now raise VersionFileError naming the file and the fix; vrg-version and the release preflight and resume catch it beside CargoVersionError. A bare KeyError or ValueError still keeps its traceback.
    • leave publish-status out of the tracking issue's stage checklist (#4946) publish-status runs after close-tracking, the last stage that writes the issue body, and reports only to the terminal, so its box stayed unticked on every finished release. Ticking it in the final write would claim a stage that has not run yet, so the checklist now lists every stage but publish-status.
    • match repository names case-insensitively in vrg-release-record check (#4949) The check now resolves the task's repo to the spelling GitHub reports before reading anything, compares record markers in any case, and prints the canonical spelling, so a task ref typed in another case finds its record. The reference page no longer describes a case-sensitive match.
    • delete the dependency-update branch once its PR merges (#4952)
    • wait for a settled mergeable status before reporting a conflict (#5067)
    • fix(pr-await): wait for a settled mergeable status before reporting a conflict

    vrg-pr-await now applies vrg-finalize-pr's conflict settle rule (#4998): a conflict ends the wait only once GitHub has reported it at the same head for two minutes, and a new head restarts the clock. It reuses finalize_watch.ConflictSettle and CONFLICT_SETTLE_SECS rather than a copy. standing_block's one-read judgement is unchanged. Refs #5036

    • fix(pr-await): wrap the docstring lines the settle change lengthened

    • check the minimum gh version in every vrg tool that calls gh (#5068)

    • fix(gh): check the minimum gh version in every library gh call

    Route every direct gh call outside vrg-gh through github.require_gh: _gh_env calls it before minting a token, so every gh call github.py makes (and release's streamed gh run watch) is checked, and the two gh calls in cd_runs and the package-index gh calls call it directly. An old gh is now refused with the version required instead of failing with gh's own unknown-flag error. Ref #5046.

    • fix(gh): exit cleanly when a vrg tool refuses an old gh

    Map GhVersionError at the cli_main boundary to a one-line message and exit 1, so a vrg tool other than vrg-gh refuses an old or missing gh the same way vrg-gh does instead of with a traceback. Ref #5046.

    • style(gh): format the gh version boundary test

    • fail a bump whose text replace leaves a version file unchanged (#5052)

    • type lifecycle PRs as lifecycle in the Pending release section (#4619) classify() now types a lifecycle/* head branch as ChangeKind.LIFECYCLE, and the open-PR section maps it instead of checking its own copy of the prefix, so both sections type these PRs the same way. The Pending release summary line counts lifecycle PRs apart from other PRs.
    • check GitHub for an existing PR when run from inside a worktree (#5037) Run from inside a worktree, vrg-submit-pr now asks GitHub for the branch's PR as the root picker does: an open PR is reported as in flight with nothing submitted, and a PR merged at the reported head refuses the run as cleanup. The root picker's choice is not asked again.
    • hold back a worktree whose PR was closed without merging (#5038) A PR closed without merging at the reported head is cleanup in vrg-submit-pr too, as vrg-repo-status and the finalize sweep already count it. The root picker, --all/--select and a run inside the worktree hold the worktree back, name the closed PR, and give two ways on: reopen it on GitHub, or run vrg-finalize-pr --cleanup-only. No new PR is opened at that head. vrg-repo-status and the shared removable rule are unchanged.
    • skip merge commits in git-cliff without a parse warning (#4592) git-cliff warned on every release that it skipped commits it could not parse. Reproduced with -vv on vergil-fixture-rust-app's v0.1.1 and v0.1.6 ranges and on vergil-tooling's current range: every skipped commit is a merge commit (Merge pull request #N from .../release/post-X or .../deps/update-X), whose changes are the merged commits listed on their own. A false positive, so both cliff configs now give a git- or GitHub-written merge subject a merge type and skip it on purpose; the generated notes are unchanged, and a hand-written unconventional subject still warns. Ref vergil-project/vergil-tooling#4592.
    • set the bumped crates in Cargo.lock before the lockfile refresh (#4593) A Rust back-merge bump wrote Cargo.toml, then ran cargo update --workspace through vrg-container-run. That run builds the dev image for the new branch, and its cargo fetch --locked warmup met the stale lockfile, logging cargo's error and a warmup skip on every release. bump now sets the bumped workspace crates' own Cargo.lock entries (and their versioned references) to the new version first, so the warmup sees a consistent lockfile and its --locked check stays as it is. cargo update --workspace still runs after it. A lockfile that does not parse, or whose entry cannot be set, fails the bump with every file restored. Checked on vergil-fixture-rust-app: after the edit, cargo fetch --locked passes and cargo update --workspace --locked changes nothing. Ref vergil-project/vergil-tooling#4593.

    CI¶

    • pass the App secrets to the shared docs workflows (#5058)

    • ci(cd): pass the App secrets to the shared docs workflows

    • feat(repo-init): pass the App secrets to the generated cd-docs call

    render_cd_workflow now emits an explicit APP_CLIENT_ID / APP_PRIVATE_KEY secrets map on the generated docs job, so every repo vrg-repo-init creates passes the App secrets to cd-docs.yml (spec 5.6 of epic vergil-project/.github#1494) and the hand-written cd.yml parity test holds. Widened per the scope change on #4965.

    Documentation¶

    • bring the docs in line with the trusted-content epic (#5066) Documentation review for epic vergil-project/.github#1467: the hook guard's content-read refusal, the trust gates in the release preflight, the trust layer and its guard test, the trusted-authors check in the config audit, the publish order, the disabled lifecycle job, and the stale vrg-resolve-tracking-issue caller.
    • fix the nested backticks in the Install record line (#5055)
    • drop license-checker from the ts-node image docs (#4734) The vergil-containers ts-node images no longer ship license-checker (released in vergil-containers v2.1.49), so the docs stop listing it as an image-owned tool. The TypeScript license gate is vrg-npm-license-gate.
    • correct three wordings: vrg-validate --markdown exit codes, type_label, bump() check order (#5070) The vrg-validate exit-code row now gives --markdown's codes, the PendingChange.type_label docstring lists lifecycle, and the bump() comment says the Cargo.lock check runs after the version files are written, under the rollback. Text only; no behaviour change.

    Features¶

    • require gh 2.97.0 or newer and check it before running gh (#5048)
    • feat(vrg-gh): require gh 2.97.0 or newer and check it before running gh

    vrg-gh's run job-log passes gh api --allow-escape-sequences, which gh added in v2.97.0. vrg-gh now refuses an older, missing or unreadable gh with a message naming the version required, instead of gh's unknown-flag error. The version is cached per gh binary (path, size, mtime) so the check adds no gh call to each invocation. The vrg-host manifest gains a minimum field, set for gh, which status reports as an ERROR when unmet.

    • keep the install's reported version and commit in the release record (#4945) When the install stage's commands report what they installed, in a line holding 'installed vX.Y.Z (commit )' as vrg-tooling-install prints, the stage records that release and commit in the state block (install_version, install_commit) and each Released: record names them in its Install line. An install that reports neither keeps the plain 'ran' wording. Ref #4945.
    • restrict updates to main (#5061) Add the "Main updates" ruleset (update rule on main, bypass: the admin role only, since the human merges every release PR) and the "Agent audit markers" ruleset (update, creation and deletion on vergil/agent-audit/*, bypass: the admin role and the automation App) to the desired GitHub config, and document both. Ref vergil-project/vergil-tooling#4772.
