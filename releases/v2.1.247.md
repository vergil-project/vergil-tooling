
# Release 2.1.247 (2026-10-17)

## Bug fixes

- **report a CD watch timeout as result-unknown and name both batch post-checks (#3317)**
The CD watch deadline was a fixed 1800s, below vergil-containers' routine ~43m CD (run 38973347564 took 43m31s), and a timeout was reported with the same headline as a failed run. The default is now 5400s (90 min, about 2x the longest known CD), overridable with VRG_CD_TIMEOUT, validated like VRG_CHECKS_TIMEOUT (a malformed value raises). A timeout gets its own headline (still in progress after Ns; result unknown) with the run URL and re-check instructions, and still fails the stage.

The end-of-batch vrg-finalize-pr --cleanup-only runs validation and the CD check, but every batch labelled a non-zero exit as validation. The shared post-step is now named post-checks and says 'end-of-batch post-checks (validation + CD check)', defined once in lib/pr_workflow/batch.py for all three batch paths.
