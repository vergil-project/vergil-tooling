
# Release 2.1.300 (2026-11-11)

## Bug fixes

- **allow dropping a planning item once its development epics are closed (#4184)**
vrg-intake-route drop refused a planning item whenever an Epic: marker was recorded, even when that epic and all its tasks were closed, leaving a dead planning item no route could clear. Drop now uses the same guard as defer (#4071): it refuses only while a development epic of the item (named by an Epic: marker or carrying a Planning: line for it) is open. Ref #4170.

- **stop counting a followed publish-index run against the package-index timeout (#4190)**
* fix(release): stop counting a followed publish-index run against the package-index timeout

The package-index timeout now bounds idle polling only. A followed publish-index run is waited for however long it takes, up to a separate three-hour bound, and the timeout restarts when the run completes, so the index gets a full propagation window after it. The run is followed by a bounded poll of gh run view instead of gh run watch, which has no deadline. A timeout error now says which wait ran out.

Ref vergil-project/vergil-tooling#4145

* fix(release): give the index-only fallback a full window after a follow fails

When gh fails partway through following a publish-index run, restart the deadline and drop the earlier run, so the fallback polls the index for a full timeout and its error names that wait (merge review R2, #4145).

- **refuse to release a repo that does not declare [publish].release = true (#4194)**
vrg-release, and the --release/--install cascades of vrg-finalize-pr and vrg-submit-pr, now read [publish].release from vergil.toml before any side effect and refuse when it is false or absent, changing nothing. Before, a repo declaring itself unreleased (vergil-project/docs) had its release PR merged to main before the release failed at CD confirmation. Refs #4175.

- **mark human-identity deploy steps as human-run in the deployment scaffold (#4195)**
The deployment-task scaffold called every deploy step agent-safe, so steps such as vrg-github-repo-config apply (which needs administration=read) were run under the agent identity only to report blocked. Add a Human-run steps section: the agent checks preconditions, hands the human a paste-ready command, and verifies the result with an agent-runnable check such as vrg-github-repo-config diff. Ref vergil-project/vergil-tooling#4176

- **print the full --help to any identity; run identity gates after parsing (#4196)**
vrg-submit-pr, vrg-ruling-reply, vrg-scope-change, vrg-promote and vrg-update-deps ran their agent-identity gate before argument parsing, so an agent's --help got a refusal or a short note instead of the usage. The gate now runs after parse_args, and each human-only command's help says it is human-only and names the agent's handoff. test_help_coverage runs every covered entry point with --help and -h under an agent identity and asserts exit 0 and a usage line. Ref vergil-project/vergil-tooling#4178

- **retry transient errors when minting App tokens and record GitHub's request ID (#4187)**
* fix(github): retry transient errors when minting App tokens and record GitHub's request ID

The JWT requests behind get_installation_token now retry a 401, 429 or 5xx with lib/retry's backoff and attempt limit, logging each retry with its request ID; a persistent failure still raises AppAuthError once the retries run out. The AppAuthError detail now carries the X-GitHub-Request-Id header next to GitHub's message. Ref #4168.

* fix(github): word the App token retry warning so semgrep does not read it as a logged secret

Semgrep's python-logger-credential-disclosure rule matched the word 'token' in the retry warning's message. The call logs only the HTTP status line, the endpoint path, GitHub's request ID and the retry counters; the JWT is never logged, which test_github already asserts. Rename the message to 'GitHub App installation request' rather than suppressing the rule. Ref #4168

- **size the checks deadline from measured CI and tell a slow check from a stuck one (#4204)**
* fix(github): size the pending-checks deadline from measured CI: 1800s -> 4500s

A vergil-containers full image-tree build (CI run 43034784731, 36.5 min) outlasted the 1800s checks deadline by about 6 min. 4500s (75 min) is roughly 2x that run, the way the CD watch is sized; the comment now cites the measurements. Refs #4200

* fix(pr-merge): tell a slow check from a stuck one when the check wait runs out

At the deadline the waiter now probes each pending check's backing Actions run and records the ones still in progress on ChecksTimeoutError.running. The merge abort then says such a check is still running, not stuck, names its run URL, and advises waiting for it and resuming, instead of re-running the job; a check with no run keeps the re-run / close-and-reopen advice. Refs #4200

* fix(github): call a timed-out check running only when its own job is in progress

The deadline probe read the workflow run's status, which stays uncompleted while a job sits queued for a runner or another job of the run is still going, so a queued job was also told to wait. It now reads the job itself (new job_status) and lists only in_progress jobs; the message also advises re-running a job whose log has stopped making progress. Refs #4200


## Build

- **run a strict mkdocs build of the site docs in vrg-validate (#4189)**
* build(validate): build the site docs with mkdocs build --strict in the custom stage

Add scripts/bin/validate-custom, which vrg-validate's custom stage runs: it stages a temporary copy of docs/site as CI's docs build does (offline) and runs mkdocs build --strict, so a deleted or renamed page that is still linked fails local validation. mkdocs-material joins the dev dependency group so mkdocs is in the project venv. Scoped to vergil-tooling only, per the scope ruling on #4115.

* build(validate): run the strict docs build from a shell validate-custom

common's shellcheck lints every file under scripts/bin as shell, so validate-custom is now a bash wrapper and the build lives in scripts/dev/check-site-docs.py. The wrapper runs it through uv run in the project venv, since PR CI's quality / custom job runs the released vrg-validate with the venv off PATH.

* build(validate): take mkdocs-material from a non-default site-check group

Per the merge-review ruling on R1: mkdocs-material moves out of the default dev group into a site-check group that only validate-custom uses, through uv run --isolated --group site-check. The project venv never gains mkdocs, so the PR docs build, vrg-container-docs and the docs deploy all keep the docs image's mkdocs.


## CI

- **run package CI on the dev- package images until the Ubuntu 24.04 cutover (#4203)**
The Canonical DNS outage of 2026-11-11 breaks install-test in prod-pkg-ubuntu, whose mirror list has only ubuntu.com hosts. Pass container-prefix: dev so the package job uses dev-pkg-ubuntu, which carries fallback mirrors, until the cutover release (vergil-project/vergil-containers#789) publishes them in prod-pkg-ubuntu. The generator-parity test now expects and strips this temporary override. Ref #4202


## Chores

- **remove vrg-xdist-sync now that the pytest-xdist rollout is done (#4185)**

## Documentation

- **point the nFPM hint and the fast-fail apt docstring at the package toolchain image (#4183)**
The epic vergil-project/.github#607 sweep: nFPM now comes preinstalled in the package toolchain image, and os-prereqs.sh was removed from actions/package/setup, so the nfpm-missing hint and the repo_setup apt-options docstring named a source that no longer exists. Ref #3758

- **give each parallel agent its own scratch directory in the prompt contract (#4192)**
Parallel sub-agents shared the session scratchpad, and one overwrote another's helper script. The agent prompt contract now requires a private scratch directory field and a rule to use only it for temporary files; the git-workflow guide's filled-in example follows. Ref vergil-project/vergil-tooling#4171.

- **say when to use an upstream refresh and when a dependency update (#4193)**
Add a 'Which mechanism do I use?' section to both reference pages, built on one test: does the repo's code depend on the input, or does the repo deliver it. Name the current users of each mechanism and link vergil-project/.github#470 for the expected merge-policy change. Ref #4172.


## Features

- **run git-cliff in the dev container through vrg-container-run (#4191)**
* feat(release): run git-cliff in the dev container through vrg-container-run

vrg-release no longer needs git-cliff on the host. The changelog and release notes are generated by git-cliff in the repo's dev container: the bundled cliff configs are mounted read-only through DOCKER_EXTRA_VOLUMES and the output paths are relative to the repo root, the container's working directory. Preflight now checks for a reachable container runtime instead of git-cliff on PATH, and git-cliff leaves the vrg-host dependency manifest.

- **add APT::Update::Error-Mode=any to APT_FAIL_FAST (#4201)**
apt-get update now fails when no mirror can serve an index, instead of warning and leaving the next install to fail on a misleading 'Unable to locate package'. This matches the 80-vergil-fast-fail apt.conf that pkg-ubuntu bakes in (vergil-containers#837). Only apt-get update reads the key, so it is inert on install and purge. Every caller runs noble (apt 2.8.4) or resolute (apt 3.x), both well past the apt 2.1 that introduced it.
