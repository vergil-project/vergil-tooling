
# Release 2.1.317 (2026-11-16)

## Bug fixes

- **refuse [ci].integration-tests = true before anything is pushed (#4463)**
No vergil-actions CI job produces the test / integration / <version> check the CI-gates ruleset requires when the setting is on (#2721), so such a repo could never merge. vrg-github-repo-init now refuses --integration-tests at argument parsing, before step 1 creates the repository, and a yes answer or an adopted or resumed vergil.toml that sets it in step 3, before step 8 makes the first push. The CI-gates guard shared with vrg-github-repo-config names the setting as the cause of the integration contexts and says why. The config loader still accepts the key.


## Features

- **run the strict mkdocs build of the docs / docs gate in vrg-validate (#4461)**
* feat(validate): run the strict mkdocs build of the docs / docs gate in vrg-validate

vrg-validate gains a docs stage (--check docs) that stages the docs sources as CI's docs job does (offline, the nav patch on mkdocs.staged.yml, every staged path gitignored) and runs mkdocs build --strict on them, through uv run --frozen for a Python repo as in CI, so a broken internal link fails local validation. A repo with no docs/site/mkdocs.yml passes the stage with a notice, as the CI job does. The staging-output list and its gitignore guard move to lib/docs, shared with vrg-container-docs. Ref #4446.

* build(validate): drop the custom validator's duplicate strict docs build

The docs stage now runs the strict mkdocs build, so scripts/bin/validate-custom and scripts/dev/check-site-docs.py go, with the site-check dependency group that only they used. Ref #4446.
