# Release 2.1.351 (2026-11-27)

## Bug fixes

- **report not-accepted content as ignored, not untrusted (#5154)**
  report_skipped printed every skipped item as 'skipped untrusted content', so content from a trusted role that a reader leaves out by design (cause not-accepted) read as a trust failure. Such items are now reported as 'ignored content from a trusted role this reader does not accept', and under GitHub Actions they are counted on their own line, apart from the untrusted, deleted and wrong-type causes. No verdict changes.
- **report the PR it opened when a later step fails (#5198)**
  A failure after gh pr create now names the PR's URL, the head it opened at and the step that failed (recording the submission, the provenance check or turning auto-merge on), and the summary no longer says no PR was opened.
- **name each recorded issue in release-records, not the tracking issue (#5221)**
  The tracking-issue body writes no longer echo the URL gh issue edit prints, and release-records prints one line per issue: posted or found existing, with the issue's URL.
- **carry the Deferred from: line forward on a defer refresh (#5224)**
  A refresh of an already-deferred item now copies the Deferred from: line of its latest trusted deferral record that has one, and says on stderr when there is none to carry.
- **keep release worktrees during cleanup while a release tracking issue is open (#5284)**
  * fix(release): keep release worktrees during cleanup while a release tracking issue is open

  Cleanup that judges what is removable (vrg-finalize-pr's sweep and its --clean-dirty clear) keeps every release/* worktree while an open, trusted release tracking issue exists, decided by worktrees.release_protection; a failed read counts as protected and fails the run. Every worktree removal is logged on stderr and in the run log (worktrees.log_removal), including managed_worktree.remove_worktree and the release's own teardown-worktree and supersede removals. A release whose worktree is gone before teardown-worktree fails with ReleaseWorktreeVanished, naming the path.

  Ref vergil-project/vergil-tooling#5187

## Features

- **show the branch in the watch-status table (#5223)**
  The table gains a BRANCH column between PR and TITLE, taken from the branch the trust layer confirmed, or - for a PR it did not confirm.
- **relax the provenance check for the one PR path (#5283)**
  Any trusted identity may now arm, or merge at clean status, a same-repo PR whose branch has a trusted author, whoever authored it (epic vergil-project/.github#1664, spec 5.1 and 5.9). pr_provenance.evaluate takes the required same_repo and branch_trusted arguments, which check_pr reads from the PR. Arming events, and on such a PR its merge and the merge's close, are no longer counted as involvement, in pr_actors and in the daily audit alike. The audit's actor check accepts the same arm and merge. Fork PRs, untrusted branches and every other forbidden action stay violations.

  Ref vergil-project/vergil-tooling#5248

- **add the one PR path and arm vrg-submit-pr's PRs through it (#5288)**
  * feat(pr-path): add the one PR path and arm vrg-submit-pr's PRs through it

  lib/pr_path.py holds accepts, merge_method and arm (release-lock spec 5.1, 5.4). arm reads the PR behind the known-resource retry, then runs the path's admission rule, the provenance check and, for an agent-involved PR only, the gates in a clone of the PR's own repo (the caller's, checked, or a fresh one), works out the merge method from the PR and enables auto-merge pinned to the head, merging directly at clean status. MergeMethod gains MERGE; the enable helper becomes private to the path. vrg-submit-pr arms through pr_path.arm. Refs vergil-project/vergil-tooling#5249

  * test(pr-path): cover every failure of the one PR path

Standalone vrg-update-deps and the release's update-deps stage both reach it through run_update. Ref vergil-project/vergil-tooling#5252.

- **add push mode, vrg-submit-pr --push judges a head before pushing it to an open PR's branch (#5291)**
  * feat(pr-path): add push mode: vrg-submit-pr --push judges a head before pushing it to an open PR's branch

  pr_path.push_to_open_pr finds the branch's open PR into develop and, at the new head, runs the path's admission rule, the provenance check and the agent gates (finalize_watch.gates_before_push, which judges a head only in the clone) before pushing it, with a lease for a rebased head. An agent pusher makes the PR agent-involved. A head that fails is not pushed, and auto-merge is never touched. vrg-submit-pr --push [--force-with-lease] is its command line (release-lock spec 5.4). Refs vergil-project/vergil-tooling#5250

## Testing

- **clear GITHUB_ACTIONS and the trusted-authors variables for every test (#5279)**
  A suite-wide autouse fixture now clears GITHUB_ACTIONS, VRG_TRUSTED_AUTHORS and VRG_AUTOMATION_APP, so a test inherits neither the CI job's Actions environment nor a host's trusted-authors copy; a test of the Actions behaviour sets them itself. The per-test delenv lines (and five fixtures that held only one) are redundant and removed, along with the monkeypatch parameters they leave unused. Ref #5087
- **pin that submit's record read and vrg-issue-read agree on a human scope change (#5199)**
  Submit's merge-review gate reads the merge-review records through a comment stream narrowed to the agents role, so the human's scope-change comment is judged not-accepted there: trusted, but left out by design. vrg-issue-read reads every role and prints it as the human's. The two reads agree on trust; only the report line called it untrusted, and the previous commit's report change already settles that entirely, with no verdict change. This adds a test on a comment of that shape covering both reads, and notes the behaviour in the records() docstring.
- **re-capture the RHEL 9 dnf fixtures and show the repo keyring before the race (#5285)**
  Re-ran capture.sh in prod-pkg-rhel:9. The race case runs with the vergil key already in dnf's repo keyring; the import block in its stderr is dnf 4.14 re-importing the repo key (named by its signing subkey 0xB8142851) and retrying after the bad repomd signature. capture.sh now lists that keyring before the race, and the fixtures README explains why the RHEL 9 race and declined-import stderr are identical. Refs #5209.
