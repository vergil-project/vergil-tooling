# Release 2.1.322 (2026-11-17)

## Bug fixes

- **surface git failures in the release worktree setup as a ReleaseError (#4442)**
  adopt_worktree now turns a failed git worktree add (such as the release branch checked out in another worktree) into a ManagedWorktreeError naming the branch, the worktree and the recovery, with git's output as its detail. The release preflight passes that detail on, and translates any other git failure while acquiring the worktree, on the fresh and the resume paths, into a ReleaseError instead of letting a raw CalledProcessError escape.
- **line-buffer stdout so the PR poller's lines are logged as they happen (#4596)**
  Under GitHub Actions stdout is a pipe, which Python block-buffers, so the mechanized-PR poller's lines reached the step log only when the step ended, all stamped with its end time. vrg-upstream-refresh now switches stdout to line buffering before it runs any mode, so the log shows the real order and times.
- **refresh Homebrew metadata before reading brew latest versions (#4609)**
  * fix(host): refresh Homebrew metadata before reading brew latest versions

  brew info reads Homebrew's local cache and never refreshes it, so a stale cache made vrg-host status and upgrade report an outdated brew tool as current. latest_version now runs brew update once per process before any brew info latest probe; if the refresh fails, every brew dependency reads latest-unknown (WARN), never current, and the CLI warns on stderr. Corrects the manifest comment's auto-update assumption. Ref #4582

  * test(host): check status refreshes Homebrew metadata too

- **restore the bumped files when a version bump fails (#4610)**
  * fix(version): restore the bumped files when a version bump fails

  bump() now saves every path it may write (VERSION, the language manifest, the secondary version files and the lockfile) before writing, and on any failure, the lockfile step's included, puts them back and re-raises, so a failed bump never leaves a half-bumped tree. A file that cannot be restored fails loudly with a VersionSyncError naming it. Refs #4587.

  * fixup! fix(version): restore the bumped files when a version bump fails

- **skip the CD release job on the push that creates main (#4617)**
  vrg-github-repo-init creates main by a direct push, which no release PR produced, so cd-release's CI-evidence gate failed on every new repo's first CD run. The generated release job now skips the push event that creates the ref (github.event.created); every other push to main still runs the gate. vergil-tooling's own cd.yml and the package-config example follow the generator. Ref #4580
- **name --python 3.15 in the container, VM dev and developer installs (#4622)**
  The container-cache install for an image with neither the vergil apt source nor a core Python, and vrg-vm update's dev install, now name --python 3.15, as do the dev-tree uv sync and developer-host reinstall in the docs. Task 4 of epic vergil-project/.github#1256 (vergil-project/vergil-tooling#4607).
- **tighten the Python allowed-actions list (#4628)**
  Python repos now get only the base allowed-actions patterns. Ref vergil-project/vergil-tooling#4577
- **warn when vrg-container-run runs below the repo root, and name the repo root when no language is set (#4630)**
  vrg-container-run now warns on stderr, naming both paths, when the current directory is not the root of the repo it resolved, and carries on. vrg-validate's no-language --check message names the repo root it resolved. --check <kind> with no language still exits 0, per the maintainer's scope change on #4594.
- **treat repo-init's dependency-free package.json as not bootstrapped (#4632)**
  A TypeScript repo fresh from vrg-github-repo-init has a package.json with no dependencies and no package-lock.json. It counted as partly bootstrapped, so vrg-validate ran npm ci, which fails with no lockfile. unbootstrapped_manifests now also treats a package.json that declares no dependencies, with no lockfile, as not bootstrapped, so the install, typescript-tools and language stages are skipped with a warning naming package-lock.json. A package.json that declares dependencies with no lockfile still fails at install. Ref #4624

## Documentation

- **bring the upstream-refresh and automation-App docs up to date with self-merging refresh PRs (#4559)**
  * docs(upstream-refresh): match the publish deadline wording to the code and drop the pre-release note

  The publish deadline covers the clone and the patch; closing an earlier run's PR, the push and opening the PR come after the wait's remaining time is worked out, so they are not counted. The note about the older single-job workflow is out of date now that vergil-actions v2.1.79 ships the two-job workflow. The diff_changed_lines docstring now names the hash rule, which also needs the whole-file diff. Ref #4444.

  * docs(guides): name the upstream refresh among the automation App's jobs and correct the ruleset claims

  The epic made vrg-upstream-refresh publish a second automation-mode job that merges its own PR, using an in-process token source. The identity, credential, permission and git-workflow guides still named the repo-config sync as the only such job, and two security-model lists said rulesets require an approving review, which they do not (required_approving_review_count is 0). Ref #4444.

  The Go and shell overviews pointed at the retired standard-actions site; they now link the vergil-actions CI gates page under latest/, as the Python overview does. The command generator linked mapping pages on a vergil-project mq-rest-admin-python site that was never published; it now links the live mq-rest-admin-project site under latest/, using its directory-style page URLs. Ref #4490.
- **drop 'Sphinx' from the --mapping-pages-dir help (#4600)**

- **bring the TypeScript, CI and release docs up to date with the TypeScript full-cycle epic (#4631)**
  Documentation review for epic vergil-project/.github#1174. The ts-node image entry now lists only the image's tools (Prettier, license-checker); the CI evidence page says vergil-actions stages the TypeScript reports from v2.1.78; the TypeScript test page drops the claim that a library pins the window; the releasing guide records TypeScript's lockfile edit and says how the per-branch cached image picks up a vergil-tooling release (#4550), dropping the retired vergil-containers tooling pin and dispatch. Ref #4451.

- **carry every batch issue's scope for a fix to an open batch PR (#4602)**
  * feat(merge-review): carry every batch issue's scope for a fix to an open batch PR

  vrg-merge-review-request --pr reads the open PR itself. On a batch PR (more than one Closes line) the request adds batch_issues (each other issue's body and human comments), batch_commits (each commit mapped to the issue its subject names) and batch_commits_path (each commit's own patch), and leaves the batch's issues out of epic_open_tasks, so a whole-branch review judges each commit against its own issue's scope. Single-issue requests are unchanged. Ref vergil-project/vergil-tooling#4584

  * test(merge-review): cover the open-PR read failures and fix a doc code span

- **log update's resolved identity mode and each ruleset's bypass actors read back (#4605)**

  vrg-github-repo-config update now prints the identity mode it resolved (naming the App's bot login under the automation identity) and, for every managed ruleset, the bypass actors it read back, or why the list was skipped, not checked or not read. Refs #4433.

- **flag links to Vergil docs sites that are not published (#4611)**
  * feat(validate): flag links to Vergil docs sites that are not published

  The docs-links check now also refuses a vergil-project.github.io link whose site is neither a mike-versioned site nor the unversioned docs or packages site, since such a link returns 404 whatever its path. The versioned list gains the two TypeScript fixture sites, which are published. Ref #4599

  * test(validate): state the published-site sets without Yoda comparisons

- **verify the stored result against its capture record in vrg-merge-review-check (#4616)**
  * feat(merge-review): verify the stored result against its capture record in vrg-merge-review-check

  vrg-merge-review-check now reads capture-<step>.json beside the result, written by the plugin's capture hook, and refuses (rule 10, capture) a result with no record, a malformed record, one for another step or request, or one whose result_sha256 is not the SHA-256 of the result's bytes. The protocol spec documents the hook-written files and the new rule. Refs #4382.

  * test(merge-review): set a capture-record field directly in the string-type test

  * docs(merge-review): keep the private directory's lifetime in the Files section of the protocol

- **add a read-only run job-log command that fetches one Actions job's log (#4620)**
  * feat(vrg-gh): add a read-only run job-log command that fetches one Actions job's log

  gh run view --job <id> --log downloads the whole run's log archive, which fails on a run with many jobs, and the per-job log endpoint was reachable only through gh api, which the user identity is denied. run job-log calls only that one GET endpoint, built from a validated owner/repo and numeric job ID, forwards no other argument, and strips terminal control sequences from the log. It is open to every identity. Refs #4597.

  * fixup! feat(vrg-gh): add a read-only run job-log command that fetches one Actions job's log

- **allow routing an ad-hoc item to planning (#4621)**
  An ad-hoc task found too big for one PR can now go straight to planning, with the same optional sizing, instead of a detour through the deferred queue. Like defer, the route is refused while an open PR would close the item. Refs #4598.
- **install by default; --no-install skips it (#4623)**
  vrg-release now runs the [publish].consumer-refresh commands after a clean release unless --no-install is given; with none configured it says there is nothing to run and exits 0. Passing --install is a fatal error naming the new default. Until Tasks 12b and 13b, the submit and finalize cascades keep their behaviour: --install runs plain vrg-release and --release alone runs vrg-release --no-install, each built from one _release_cmd helper that every hint prints. Ref vergil-project/vergil-tooling#4562.
- **clear classic protection's up-to-date flag on develop (#4625)**
  The audit now always reads develop's classic branch protection and reports required_status_checks.strict: true there as branch_protection.develop.strict. Apply sets strict to false through the scoped required_status_checks PATCH and leaves every other classic setting, and main, unchanged (epic vergil-project/.github#1218, Task 5).
