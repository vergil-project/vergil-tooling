
# Release 2.1.250 (2026-10-19)

## Bug fixes

- **delete the branch when the dependency-update gate closes a PR (#3338)**
GitHub's delete-on-merge setting never applies to a PR closed without merging, so the gate's auto-close of a landed dependency-update PR left deps/update-<v> on origin indefinitely (vergil-tooling deps/update-2.1.244, vergil-vm deps/update-2.1.44). Preflight now deletes the head branch after closing the PR. The delete is a separate step rather than gh pr close --delete-branch, because gh exits non-zero when the close succeeds but the delete fails, which the close handler would misreport as the PR still being open. An already-deleted branch counts as deleted. Any other failure prints a warning with the manual command and is named in the prepare comment on the tracking issue; the gate still clears because the PR is closed. A test now requires every gh pr close in src/ to pass --delete-branch or say why not. Ref #3332

## Features

- **add vrg-branch-sweep to delete finished branches left on origin (#3339)**
Lists a repo's branches via the GitHub API and reports, or with --apply deletes, those whose newest PR is merged or closed with none open and whose tip still equals that PR's headRefOid. Keeps the default branch, develop, main, gh-pages, protected branches (branches API flag plus any ruleset rule from the rules-for-branch endpoint), no-PR branches and reused branch names. Per-branch errors are reported and the run exits non-zero after processing the rest. Safety net behind delete-on-merge and the delete-on-close rule (#3332).
