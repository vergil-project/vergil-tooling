# Release 2.1.328 (2026-11-19)

## Bug fixes

- **report vergil-tooling and leave its install to the release (#4745)**
  vergil-tooling's host install belongs to its own release, whose consumer-refresh reinstalls it. A new manifest upgrade value, release, marks it: vrg-host upgrade never runs uv tool upgrade for it (--all and --force included), reports its installed version as skipped (or refused when named), and status says the release installs it without claiming it is current. Ref #4603.
- **pass the automation App secrets to cd-release in generated cd.yml (#4750)**
  cd-release.yml now requires APP_CLIENT_ID and APP_PRIVATE_KEY to push the release tags (vergil-project/vergil-actions#1315). The cd.yml that repo_init generates forwards both by name in the release job's secrets map, ahead of any publisher secret; [package] repos keep secrets: inherit, which already carries them. Ref #4747.
- **guarantee ~/.local/bin on PATH for non-login remote commands (#4758)**

## Features

- **replace the confirmation and body previews with one selection table (#4746)**
  * feat(submit-pr): replace the confirmation and body previews with one selection table

  vrg-submit-pr no longer asks for confirmation or prints each PR body. It prints one compact table of the selected PRs (issues and linkage, branch, title), then runs the submit rollup. --yes/-y is removed and refused by name, like the other removed flags, and the per-issue Closes-upgrade notes are folded into the table. Ref #4744

  * refactor(submit-pr): return only the linkage keyword from _task_linkage

  Its Closes-upgrade note had no caller left once the selection table showed the linkage (merge review R1). Ref #4744

- **resolve once and install a release commit with uv (#4748)**
  * feat(tooling-install): resolve once and install a release commit with uv

  Add lib/tooling_install.py: resolve a ref to one tag and commit SHA with a single git ls-remote (peeling annotated tags), and render the locked uv tool install as shell lines (cleared UV_PYTHON* variables, --no-config, --python 3.15 --managed-python, the commit's uv.lock exported over git as constraints, named failures), plus the post-install vrg-whoami check. vergil.toml's consumer-refresh now installs the exact release tag with its lock in plain shell, and the guides document the same lines as the Mac's first install. Ref vergil-project/vergil-tooling#4738.

  * docs(tooling-install): say the release refreshes only the Mac that runs it

- **protect release tag creation (#4754)**
  * feat(github-config): protect release tag creation

  The Tag protection ruleset adds a creation rule for refs/tags/v*.*.* and refs/tags/v*.*, and its bypass list is the repository Admin role and the org automation App, threaded through compute_desired_state as the automation-branch ruleset's is. The GitHub Actions integration is never a bypass actor, so no workflow's GITHUB_TOKEN can create a release tag. Ref vergil-project/vergil-tooling#4736

  * fixup! feat(github-config): protect release tag creation

- **run consumer-refresh as the last pipeline stage, rolled up to one line (#4755)**
  * feat(release): refresh consumers as soon as the release tag exists, rolled up to one line

  The consumer-refresh stage now runs right after confirm-main and runs the [publish].consumer-refresh commands itself, instead of printing them after close-finalize and installing once the pipeline ends. A deferred publish no longer holds it. On success the stage is one check line; on failure its full output is printed below the summary and the stage fails. --no-install makes it print the commands instead.

- **install vergil-tooling with uv and remove the vergil packages (#4757)**
  * feat(vm): install vergil-tooling with uv and remove the vergil packages

  A released ref resolves once on the host and installs its commit with tooling_install's locked uv install; both release and dev installs run the post-install check. After the check, vrg-vm purges vergil-tooling, every vergil-python* and the keyring package, removes the vergil apt source, key and pin, and confirms none is left. vrg-vm create no longer bootstraps the vergil repository. classify_ref moves into tooling_install so vm_packages can import it without a cycle. Ref vergil-project/vergil-tooling#4741

  * fixup! feat(vm): install vergil-tooling with uv and remove the vergil packages

- **install vergil-tooling from one release commit with uv (#4756)**
  * feat(container-cache): install vergil-tooling from one release commit with uv

  The cache build drops the packaged apt install and renders tooling_install's uv tool install of one commit on a managed Python 3.15, into /usr/local/bin, followed by the post-install check. The cache key resolves a line pin with one git ls-remote and folds its commit SHA in as a separate hash input, while the recorded tooling value stays the exact tag; an exact pin needs no network and the build resolves its SHA. tooling_release no longer reads the package index.

  * fix(container-cache): say truthfully what an exact pin does offline

  A line pin's key now holds the commit and an exact pin's does not, so pinning the held tag no longer reuses an image built under the line pin. The error says so, names the held tag as the release to pin once the network is back, and a test pins the rebuild (merge review R1).

## Testing

- **use distinctive sentinels in the hook-environment checks (#4753)**
  The hook tests dump the hook's whole environment and asserted that no note held the word 'secret'. In CI the branch name reaches that dump through GITHUB_HEAD_REF, GITHUB_REF and GITHUB_REF_NAME, so any branch named with 'secret' failed them although nothing leaked. They now set fixed sentinel values and assert those are absent, with regression cases on such a branch. Ref #4752.
