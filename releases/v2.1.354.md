## Bug fixes

- **leave a closed child in an archived repo in place (#5312)**
  * fix(epic-rollup): leave a closed child in an archived repo in place

  The rollup's move of a closed child into its quarter archive failed the run with 'Repository was archived so is read-only' when a retire had archived the child's repo first. It now checks the repo's archived state before creating any archive, and also treats that one refusal of the move as a reported no-op; every other failure still fails the run. Refs #5212.

  * test(epic-rollup): format the archived-repo tests and type the drain helper as a generator

  * docs(epic-rollup): reword the archived-repo comment in the drain

- **read the lock again before the backstop judges a breach (#5323)**
- **take over a stale arming ref on the arm path outside a release (#5327)**
  * fix(release-lock): take over a stale arming ref on the arm path outside a release

  An arm call whose create collides now watches the other caller's arming ref. A value it sees unchanged for ARMING_EXPIRY_SECS with the PR open and unarmed is stale: with the lock free it is replaced by compare-and-swap and the call goes on through the handshake; with the lock held the PR is held and the ref left for the release. A ref that goes is recreated. So a leftover ref never leaves a PR unarmable outside a release. Ref vergil-project/vergil-tooling#5324.

  * fixup! fix(release-lock): take over a stale arming ref on the arm path outside a release

The unlock stage's refusal for an unreadable lock names the read error instead of calling it another release's lock. Ref vergil-project/vergil-tooling#5352.

- **add the lock owner, its serialised writes and the background heartbeat (#5319)**
  * feat(release-lock): add the lock owner, its serialised writes and the background heartbeat

  Adds lib/release_lock/holder.py (epic vergil-project/.github#1664, Task 21): LockOwner takes, adopts or takes over the release lock with a new token and starts a background heartbeat before it returns. One lock serialises every write. Each write is a compare-and-swap on the owner's last write; a mismatch against a sha the owner built is retried, and any other mismatch raises LockLost, stops the heartbeat and never re-takes. On a loss the lock history names the cause by the old lock's token, or the loss is reported as a change outside the tooling. refs.build_lock lets the owner know each write's sha before it pushes. Refs #5267.

- **add the arming gate and the holder's pass to the one PR path (#5325)**
  pr_path.arm writes the PR's arming ref after every judgment, reads the lock, and arms only with the lock free, renewing the ref first and bounding the arm call by ARM_CALL_BOUND_SECS (retry.bounded). A held or unreadable lock leaves the PR unarmed as held; a create collision waits for the other caller; a matching holder's pass (the lock's token) skips the handshake. vrg-submit-pr reports held and goes on to its watch; the mechanized jobs treat held, including a PR disarmed mid-wait, as success; update-deps reports held and returns with no failure record, and the release's update-deps stage refuses a held update. Ref vergil-project/vergil-tooling#5265.

- **add stale-lock reclaim and the human-only vrg-release-lock break (#5328)**
  * feat(release-lock): add stale-lock reclaim and the human-only vrg-release-lock break

  reclaim.reclaim_if_stale deletes a stale lock by compare-and-swap, records a reclaim entry and a tracking-issue comment, runs the re-arm sweep, then records a reclaim-rearm entry, recording a failed sweep too. reclaim.break_lock records first, then deletes with up to three compare-and-swap attempts while the lock is the same holder's, records break-failed when it does not land, and re-arms only once the lock is gone. vrg-release-lock break refuses every agent identity and agent signal.   Task 23 of epic vergil-project/.github#1664 (vergil-project/vergil-tooling#5269). A fresh vrg-release now runs the one-release check, syncs develop and runs the pending-deps and develop CD gates as pre-checks, reclaims a stale lock, takes the lock (refusing, with nothing disarmed, when another release holds it), quiesces develop, syncs again, always re-runs the pending-deps gate, re-judges a moved head, records the worktree in the lock and cuts. prepare writes the tracking issue into the lock straight after creating it; each tracked stage writes its stage, and the first recorded failure marks the lock broken. - **unlock and re-arm at the end of vrg-release, with stray-merge checks and the abandon step (#5331)**
  Task 24 of epic vergil-project/.github#1664 (vergil-project/vergil-tooling#5270). New tracked stages unlock and rearm run after release-records and before close-tracking, and join the stages any earlier failure holds back, so a broken release keeps develop locked until --resume finishes it. The back-merge and the release's dependency update arm with the holder's pass (run_update and arm_and_wait gain holder_pass; standalone vrg-update-deps passes none). stray.stray_merges walks develop's first-parent history after the cut, leaving out the holder's own PRs found through the trust layer. A stray merge before merge-release runs abandon.abandon_release: it closes the release PR, removes the release branch and worktree (logged), closes the tracking issue as abandoned, then releases the lock and re-arms. One found before unlock is reported on the tracking issue and the release goes on.
- **run --resume and --supersede under the release lock (#5351)**
  A resume before unlock adopts its own broken or stale lock with a new token, refuses its own live lock (naming the host and heartbeat age) and another release's, and re-takes an absent lock: it records the re-take in the lock history, quiesces develop and, before merge-release, abandons on a stray merge. A resume at unlock deletes its own remaining lock by compare-and-swap or finds none; past it no lock is read. A supersede takes over the superseded release's broken or stale lock by compare-and-swap with no tracking issue, records it in the history and on both tracking issues, and refuses a running, fresh one; with no such lock it takes a fresh lock and quiesces. Ref vergil-project/vergil-tooling#5271
