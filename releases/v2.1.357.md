# Release 2.1.357 (2026-11-28)

## Bug fixes

- **name the hand-run opener in the sync PR body (#5402)**
  A sync PR that a person opens by running vrg-github-repo-config update by hand said the repo-config sync job opened it. The body now names the login a human run opens the PR as; the App keeps the job wording. A human run whose login cannot be read is refused before any audit or clone, with no fallback to the job wording. Refs #5399
- **the one PR path retries a merge refused because the base branch moved (#5413)**
  * fix(release-lock): retry a merge refused because the base branch moved, and read a PR's state instead of asserting it

  The one PR path's direct merge and arm call now retry GitHub's 'Base branch was modified' refusal, bounded by BASE_MOVED_ATTEMPTS inside the arm call bound. The watch's failed-re-arm stop and vrg-submit-pr's finalize-failure report read the PR's state. Ref #5406

  * fix(release-lock): retry a moved-base enable only after reading the PR, and merged meanwhile is a success

  A retry of a refused enable re-issued the enable on a PR another caller had merged during the pause, and the arm reported a failure for a merged PR. Each retry now reads the PR's state and head first; a PR merged at the head is reported as merged, with no further enable or merge. The read is a new auto_merge.merged_at helper, and a failed read raises. Refs vergil-project/vergil-tooling#5406.

## Features

- **broken release groups fail the sweep (#5401)**
  * feat(release-groups): say whether a group refusal is an edit, an unreadable log, or both

  A GroupRecordError now carries the edit problems it holds and whether it holds any problem that is not an edit, so the group audit can report an edited record and an unreadable log apart. Its message text is unchanged. A RuleBreak names the member it is about (the dependency path's start), so a closed member's break can be told from an open member's. The rule reader's error set is public for the audit.

  * feat(release-groups): read the merged PRs that close a task, as the trust rule counts them

  The group audit needs each member's merged closing PRs. merged_closers reads a task's closedByPullRequestsReferences with the release's closing-reference trust rule: a PR counts only when it merged in the task's own repo and the trust layer counts its reference to the task. A truncated or malformed answer raises ClosersReadError; it never reads as no closers.

  * feat(epic-audit): report broken release groups in the audit and the sweep

  group_findings checks the live groups of every open development and proxy epic of the org's home and reports split, closed unmerged, rule, edited and unreadable findings. A closed epic is never checked, and a closed member's shipped break is never a rule finding. The audit prints a Release groups section and exits 1 with any finding; --close runs the check after the drift-close pass and the other passes. It repairs nothing.

  * test(trust-guard): register the group audit's closing-PR read as judged by the trust layer

  merged_closers reads the closing-PR fields that vrg_release_record's closing-PR read reads, and counts a PR only through trusted_closing_refs. The trust guard needs that read registered as judged, with the same fields and judge.

  * test(release-groups): cover a split whose detail leaves out an open member with no merged PR

  The split detail skips a member with no merged closing PR. The branch was not covered, so the full validate run failed on coverage.

  * test(release-groups): cover a member moved to another repo breaking the one-repo rule

  Review Focus 4 of the batch-release-unit plan asks the audit to report a member moved by hand as breaking the one-repo or the same-epic rule. The same-epic case was covered; this covers the one-repo case.

  * fix(release-groups): report an unreadable epic kind or state instead of aborting the sweep

  _open_heads read each listed epic's kind and the head's state with no guard, so one drifted or unreadable epic aborted the whole audit and lost the report. A failed read of a listed epic now becomes an unreadable finding naming it, and the rest are still checked; a missing GitHub token still propagates.

- **the tracking issue records when the release took the lock (#5398) (#5405)**
- **the whole-group rule on every PR path (#5415)**
  * feat(release-groups): refuse a PR that closes part of a release group or its members out of order (#5341)

  A release group ships as one batch, so a PR that closes some of a group's members and not the rest is refused, and so is a batch that lists a group's members out of the group's build order. pr_check reads the closing references (any repo, counted or not) and the closing keywords of the autoclose family in the body, and fails closed on an unreadable or edited group record. Spec 5.2, epic vergil-project/.github#1672.

  * feat(batch): apply the whole-group rule at batch start (#5341)

  check_hard_rules runs the whole-group rule last, with the batch's commit order: a batch holding part of a release group, or a group's members out of its build order, is refused. A lone one-member group still takes the single-issue path, since a batch needs two issues.

  * fix(release-groups): cover the malformed PR reads and drop an unused import (#5341)

  Adds the guard tests the coverage gate needs for pr_check's malformed-input refusals (a missing or non-list connection, a malformed node, a non-text body, a malformed repo name), removes an unused import, and formats the touched files.

  * feat(release-groups): apply the whole-group rule on report-ready, batch-check and every submit path (#5341)

  A single-issue report-ready refuses an issue that is a member of a release group the PR does not close whole. batch-check runs the rule over the body's Closes refs for any PR, batch or not. vrg-submit-pr runs it at the start of the gate, so every submit mode (template, --all/--select, named branch local and relay, CLI emergency) refuses before anything is pushed or opened. A batch's own report-ready keeps the rule through check_hard_rules.

  * fix(release-groups): keep the submit gate's refusal for unqualifiable refs and fake group reads in the other suites (#5341)

  The submit whole-group check leaves an issue it cannot qualify to the gate, which refuses it, as before. The test conftest for pr_workflow fakes the group records rather than the rule, so the batch hard-rule tests still run the rule for real. batch-check's test fakes the group records too.

  * fix(release-groups): read batch-check's clone once and cover the single report-ready clone refusal (#5341)

  batch-check reads this clone's repo once, before the whole-group rule, and a PR without a Closes line returns before any read. The tests cover the single-issue report-ready refusal when the clone's repo cannot be told, and batch-check on a body with no Closes line, which keeps the coverage gate at 100 percent.

  * feat(pr-path): apply the whole-group rule on every PR path arm and push (#5341)

  The one PR path judges the whole-group rule (spec 5.2) for every PR into develop, agent involved or not: arm after the provenance check, and push_to_open_pr after its provenance check. A PR that closes part of a release group, or a group's members out of build order, is refused and nothing turns on (arm) or is pushed (push). A failed read of the PR's closing data raises PRPathError and never allows. A PR that closes no issue reads no group record. The re-arm sweep, the merge watch's re-arm and the release back-merge reach the rule through arm, and each reports the refusal as a refused arm.

  Tests run the real judgments with GitHub's closing read and the group records faked (tests/vergil_tooling/group_rule_stubs.py), including the submit --push refusal and the update-deps arm tests.

  * test(pr-path): wrap the whole-group test imports and lines to the lint rules (#5341)
