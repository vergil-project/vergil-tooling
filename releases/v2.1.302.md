
# Release 2.1.302 (2026-11-12)

## Bug fixes

- **check every Closes line of a multi-linkage PR body (#4235)**
Add linkage.extract_tracking_refs, which returns every linkage of a body as (keyword, ref) pairs in order. task_drift no longer skips a body with more than one linkage line: a single-line body is handled as before, and a multi-line body has each Closes ref checked and its Ref lines ignored, so a batch PR is never skipped by the sweep.


## CI

- **revert package CI to the prod- package images after the Ubuntu 24.04 cutover (#4238)**
The cutover release vergil-containers v2.1.38 published prod-pkg-ubuntu:24.04 with apt fallback mirrors outside Canonical's domain, so the temporary container-prefix: dev override added for the 2026-11-11 Canonical DNS outage is no longer needed. Remove it from the package job, and compare the hand-written package job with the generated one whole again in the generator-parity test. Ref #4237

## Features

- **add --fixup to make a fixup commit of a branch-local commit (#4233)**
* feat(commit): add --fixup to make a fixup commit of a branch-local commit

vrg-commit --fixup COMMIT runs git commit --fixup through the same context and freeze checks as a normal commit. The target must be reachable from HEAD and not from origin/develop. The message flags are refused alongside it. Ref vergil-project/vergil-tooling#4218.

* test(commit): cover --fixup with --allow-empty and fix the line length

- **add the batch rules module (hard rules and one commit per issue) (#4234)**
* feat(pr-workflow): add the batch rules module (hard rules and one commit per issue)

check_hard_rules, check_commit_per_issue and is_batch, shared by batch-start, report-ready, submit and finalize. Both checks fail closed: a failed read refuses and names what could not be read. The hard rules include a fail-closed trusted-author check. Adds epics.issue_state and epics.issue_author.

- **allow local rewrites on unfrozen feature branches (#4232)**
* feat(git): allow local rewrites on unfrozen feature branches

vrg-git protects origin, not the local checkout. reset, clean, every pathspec checkout (checkout ., checkout -- <path>) and rebase -i --autosquash now run on a branch that is neither protected nor frozen. They are refused on develop, main and release/*, on a detached HEAD (mid-rebase, the branch being rebased is checked), and on a reported-ready branch with the freeze's own message. Unlike commit and push they fail closed when .vergil/pr-workflow.json exists but cannot be read. rebase -i/--interactive, including short clusters and abbreviations, is denied without --autosquash. Ref #4217

* fix(git): refuse rebase -i --autosquash naming another branch

rebase <upstream> <branch> checks out and rewrites <branch>, which the local-rewrite checks on the current branch never see. The interactive form now takes only <base>. Ref #4217

* fix(git): address merge review finding R1

- **add batch-start, batch-extract and batch-show (the batch marker) (#4239)**
* feat(pr-workflow): add batch-start, batch-extract and batch-show (the batch marker)

Add lib/pr_workflow/batch_marker.py, which writes, reads, extracts from and removes a batch's per-member marker in build/.vergil-state/issue-implement/<N>/batch in the main clone, and wire it into vrg-pr-workflow as batch-start (hard rules first, resume on an identical batch), batch-extract (refused while a security details file remains) and batch-show (JSON on stdout; exit 1 without a marker, 2 on any other failure, a wrong clone included). Ref vergil-project/vergil-tooling#4222

* fix(pr-workflow): refuse batch-extract when a state subdirectory cannot be searched

os.walk skipped an unlistable directory silently, so the security-details check could pass without having looked. Refuse instead, changing nothing. Ref vergil-project/vergil-tooling#4222

- **detect a batch PR, update it by rebase, re-check and rebase-merge (#4240)**
A PR whose body has more than one Closes line is a batch PR. vrg-finalize-pr cross-checks its Closes issues against GitHub's closing references, checks the commit-per-issue invariant after fetching, updates a behind batch PR with updatePullRequestBranch (REBASE) instead of update-branch, re-checks after every update and right before the merge, and rebase-merges with --match-head-commit pinned to the checked head. A squash override on a batch PR is refused, and a batch conflict or merge commit names the rebase and leased push. Single-issue PRs are unchanged.

Ref vergil-project/vergil-tooling#4226

- **publish the apt indexes by hash and keep earlier index generations (#4241)**
* feat(package): publish each apt index by hash and declare Acquire-By-Hash

Write every Packages and Packages.gz also to by-hash/SHA256/<digest> beside it and add Acquire-By-Hash: yes to Release, so apt fetches each index by the digest its InRelease names (#4230).

* feat(package): keep earlier index generations' content-addressed files published

Each index build reads index-generations.json from the live site, republishes the by-hash and repodata files of the newest [retention].generations - 1 earlier builds (each checked against the digest in its name), and writes a new manifest with its own generation first. Older generations are pruned when the new site replaces the old one. Default 3 generations, minimum 2 (#4230).

- **carry an ordered issue list in the workflow state and report-ready (#4223) (#4242)**
WorkflowState gains an optional ordered issues list, still at schema version 2, written only for a batch, with all_issues for either shape; init_state takes issues. read_pr_fields returns the comma-joined issues. report-ready takes a repeated --issue, runs the per-issue refusals on each, refuses a re-run whose ordered list differs from the recorded one, runs the batch hard rules and the commit-per-issue check before any push, and removes the batch markers once the state is recorded. A single --issue is unchanged. Ref #4223

- **per-issue checks and one Closes line per issue for a batch (#4243)**
* feat(submit-pr): run per-issue checks and write one Closes line per issue for a batch

vrg-submit-pr now reads every issue of a report-ready record (the comma-joined issues field) on the template, named-branch and serial batch paths. Each issue runs the per-issue refusals and gets its own linkage line, so a batch PR body carries one Closes line per issue. A batch is re-checked against the hard rules and the commit-per-issue invariant on the head the PR opens at, against a freshly fetched origin/<target>, before any push or gh pr create. build_pr_body takes a list of (linkage, ref) pairs; a single pair renders the single-issue body unchanged. The CLI emergency mode stays single-issue.

* fix(submit-pr): fetch only the target before a batch push so the force-with-lease guard holds

The batch re-check fetched the PR branch on every path. On the paths that push right after (template mode and the serial batch), that refreshed refs/remotes/origin/<branch>, the lease --force-with-lease holds, so the push could overwrite commits pushed elsewhere. Only the relay path, which never pushes, now fetches the branch.
