## Bug fixes

- **read queue markers and notes only from trusted comments (#4919)**
- **count outcomes and dedup comments only from trusted authors (#4920)**
- **trust security-record lines only from trusted bodies (#4924)**
- **stop only the item whose comments cannot be read in the queue views (#4969)**
  Spec section 5.3 of epic vergil-project/.github#1467 makes the queue views batch runs: a read failure on one item's comments now stops that item through trust.BatchStops, the view carries on with the rest, and vrg-queue exits 1 after listing every stop. A --json run with a stop prints nothing on stdout, so a partial list is never taken for the whole. BatchStops gains a read-failure detail and a stopped accessor, and names a read failure by repo, number and field. Ref vergil-project/vergil-tooling#4966
- **read parents and blockers only from trusted bodies, and roll up only trusted closes (#4922)**
- **never attach or route outsider-opened issues (#4928)**
  Orphan attach leaves out an issue whose author holds no role, reporting it metadata-only with a clean exit, and every intake route, sizing included, stops on one before anything resolves or is written. The trust layer gains outsider_opened to name the author's record. Narrowed scope: the activity log moves to #4970.
- **find PRs by branch only among same-repo trusted PRs (#4917)**
- **attest only the commit's same-repo PR and its own check runs (#4918)**
  The release PR is the merge commit's one merged same-repo PR with a trusted author, read through the trust layer, with no first-PR fallback. The CI run must be built from the repo itself, and only its own check suite's check runs and the GitHub Advanced Security scanner checks count (GHSA-r4j2-cwcp-xg56, GHSA-q6hx-8c85-9f56).
- **adopt fix tasks and release issues only when trusted (#4926)**
  The dependency-update fix task is reused only when its body is trusted, the deps PR's Fix task link is read only from a trusted body, a completed fix-task close clears the gate only when a trusted identity closed it (any other close stops the release), and an untrusted release: issue is reported, never a blocker of a fresh start (GHSA-777j-j57r-92ff).
- **classify PR identities and review comments through the trust layer (#4927)**
  PR provenance takes every identity's role from the trusted-authors configuration through the trust layer: a login with no role is untrusted, never human, and may not author, edit, close, reopen or merge the PR or turn auto-merge on; an untrusted approval is reported, not a violation. vrg-pr-review-comments prints only the inline comments the trust layer trusts, with the body it read, and reports the rest (GHSA-q6hx-8c85-9f56).
- **report an API fallback failure as exit 2 (#4975)**
  A git or GitHub API failure in the commit-to-pulls fallback was suppressed into the generic 'cannot determine PR' exit 1. It now exits 2 with the error text, as the commit-read failure does and the CLI reference documents. Ref #4967
- **leave outsider-opened and outsider-closed issues out of the activity log (#4976)**
  * fix(activity-log): leave outsider-opened and outsider-closed issues out of the activity log

  Adds a batched trust-layer read: search_items can judge each result's latest close in the same call (judge_close), and search_window splits a date window that would meet the search cap, failing loudly when a single day exceeds it. vrg-activity-log reads its closed issues through it, so its GraphQL calls grow with result pages, not with issues. Ref #4970.
