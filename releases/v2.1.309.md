- **add the automation identity mode, verified against the token (#4351)**
VRG_AUTOMATION_APP names the org automation App. With it set, resolve() requires the token's GraphQL viewer login to be <slug>[bot], refuses any agent signal alongside it, and returns AUTOMATION. Without it, resolution is unchanged and makes no API call. Adds lib/automation_identity (automation_app_slug, automation_app_id, verify_token_is_app) and states in its docstring what the check trusts. Ref vergil-project/vergil-tooling#4300.

- **add the Rust floor and toolchain-file checks (#4352)**
* feat(versions): add the Rust floor and toolchain-file checks

* style(versions): format the Rust extension tests

- **allow auto-merge, add the automation-branch ruleset, and treat an empty bypass read as unread under automation (#4356)**
The desired state now sets allow_auto_merge=True and adds an Automation branches ruleset on refs/heads/automation/** whose only bypass actors are the org automation App (Integration, its numeric ID) and the admin role. It restricts creation, update and force-push, never deletion.

compute_desired_state takes skip_bypass and automation_app_id in place of app_mode. bypass_actors are skipped only for an App token that is not the automation identity; every other run resolves the App ID through automation_app_slug and automation_app_id, and apply and repo-init always do. Under the automation identity a non-empty desired bypass list that reads back empty is a BypassUnreadable, a NotChecked entry, so the audit is incomplete and apply refuses before writing. A human run still treats it as drift and converges it.

Bypass lists are compared as sets, and a skipped bypass list is refused at write time instead of being written as an empty list.

Ref vergil-project/vergil-tooling#4305 (epic vergil-project/.github#1064, plan Task 5).

- **packaged cargo-deny policy for rust (#4358)**
Ship configs/rust/deny.toml with the reviewed _RUST_LICENSES_ALLOWLIST and run the rust audit as cargo deny --config <packaged> check, so Rust repos inherit the fleet license, advisory, ban and source policy. Ref vergil-project/vergil-tooling#4347.

- **operational task bodies from a sectioned file (#4359)**
Let --kind validation|deployment take Intro, Preconditions, Procedure, Acceptance and (deployment only) Human-run steps from a --body-file, keeping the scaffold frame. Retrospective still refuses --body-file. Ref vergil-project/vergil-tooling#4348.

- **add the update subcommand and deprecate apply (#4360)**
update converges the GitHub side as apply does, then runs every managed-file fixer in a fresh clone of develop and proposes the result as one auto-merging sync PR on automation/repo-config-sync/<run-id>. It refuses the agent identity modes by name and runs for the human and the automation App. Exit 0 is in sync or a PR opened with auto-merge confirmed; 1 is drift it could not fix, with the PR still opened; 2 is anything not audited or not converged, including a setting not checked, which opens nothing. apply keeps its behaviour and prints a deprecation notice naming update. Refs vergil-project/vergil-tooling#4306 (epic vergil-project/.github#1064, Task 6).
