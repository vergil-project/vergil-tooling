  Epic vergil-project/.github#1672, phase 1 Task 2. parse_record and render_record hold the release-group record grammar. read_log and groups_of take the record only from the human and agents roles, pick the latest revision, and scope each failure to its group, or to the whole epic where no group is named.

  * feat(release-groups): add vrg-release-group list

  Read-only list of an epic's release groups, plain or as JSON, with --group to narrow it. Exits 0 on a read, 1 on a refusal or read failure, 2 on a usage error. Adds the console script and its entry in the CLI tools overview.

- **chain each batch commit's record to the commits before it (#5371)**
  * feat(merge-review): record each merge-review record and approval with its time

  A merge-review record now carries the time its comment was posted, and a verified approval carries the time of the approving reply. The stored record line is unchanged, so no record needs migrating. The batch chain in the gate reads these times (epic vergil-project/.github#1672, spec 5.4).

  * feat(merge-review): chain each batch commit's review record to the commits before it

  The merge-review gate covers a batch's commits in order. Commit k is covered only by a record or approved exemption whose fingerprint matches commit k and whose time is at or after the review of commit k-1. A changed earlier commit therefore voids every later record until each is reviewed again. A clean rebase voids nothing, records built in order pass unchanged, and a whole-change record still covers every commit (spec 5.4).

  * fix(merge-review): fail closed on a record time the gate cannot read, and format the chain

  * fix(merge-review): accept any mapping of files in the chain test helpers

- **add the group rules and the holder check (#5372)**
  * feat(release-groups): expose the in-flight PR, relay and local ready-state reads

  The group rules' holder check reads the same trusted sources as the in-flight marks. open_pr_marks maps each issue to the open counted PRs that mark it, ready_relays maps each ready relay branch to the issues it hands off, and ready_local_branches does the same for worktrees whose local pr-workflow.json is ready. Each raises InFlightError on a failed read. Part of vergil-project/.github#1672.

  * feat(release-groups): add the group rules and the holder check

  check_group_rules returns a RuleBreak for each rule of spec 5.1 a group breaks: each member an open task (not an epic or archive) in one repo under the group's epic, not operational, not a documentation review; a size of 1 to MAX_BATCH; the epic a development epic or a proxy of one with sound links; and no dependency path from one member to another through an open task outside the group. dependency_paths walks Blocked-by lines and native links transitively, across epics and repos, never through a closed task. holders reports the open PR, the handed-off batch (relay or local) and the batch marker that hold a task back. Every failed read raises GroupRuleReadError. The design-question rule is not checked. Part of vergil-project/.github#1672.

- **record a middle batch commit and add the read-only batch-gates probe (#5376)**
  * feat(merge-review): record a batch member's own commit wherever it sits

  A batch member's merge-review record now covers its own commit, the one whose subject names the issue, with its fixup commits folded in, from that commit's parent. The change no longer depends on the marker's base_sha or on the issue being the last one on the branch, so a middle commit can be reviewed again before handoff, and a clean rebase onto a moved develop changes no issue's change. A fixup of a commit that comes after another commit is refused until it is folded.

  * feat(batch): add the read-only batch-gates probe

  vrg-pr-workflow batch-gates [--json] judges a batch's merge-review gate before report-ready, commit by commit, as vrg-submit-pr does. It reads the batch's issues from the branch's markers, fetches origin/develop, and writes nothing. It exits 0 when every commit is covered, and 1 when one is not, on a read failure, or after report-ready has removed the markers. The rule is one walk in agent_gates, now exposed as evaluate_commits with a verdict per issue; evaluate keeps its reasons and order.

  * docs(batch): describe the batch member record and batch-gates

  The merge-review guide and the CLI reference now give a batch member's change as its own commit with its fixups folded in, from that commit's parent, and document the batch-gates probe with its JSON shape and exit codes.
