
# Release 2.1.289 (2026-11-08)

## Bug fixes

- **list up to 1000 rows in _find_epic_by_title and refuse a truncated list (#4040)**
gh issue list returns 30 rows without --limit, so an org with more than 30 open epics under the same labels could miss an older one and ensure_standing_epic would create a duplicate. The lookup now passes --limit 1000 and raises EpicListTruncatedError (a ValueError) when the result reaches it. Ref #3822.

- **recover a one-off re-link refused as a duplicate sub-issue and report link failures cleanly (#4043)**
* fix(intake-route): clear the stale parent link when GitHub refuses a one-off re-link as a duplicate sub-issue

- **write the guest ~/.claude config atomically in copy_claude_config (#4044)**
Each of CLAUDE.md and settings.json is now written to a mktemp file in ~/.claude, given its final mode (644, plus a-w for CLAUDE.md), then renamed into place with mv -f. A concurrent reader never sees an empty or partial file, and a failed write removes the temp file, exits non-zero and leaves the existing file and its mode untouched. Ref #3987.

- **tell an unreachable VM apart from a missing guest settings.json (#4045)**
The guest settings.json read now masks every file condition into a zero exit with a status line, as read_fingerprint does, so a failed round-trip raises VmUnreachableError naming the connection, and a missing or unreadable file is reported as such. Ref #3990.

- **resolve the PR's own repo in the provenance check and the required-check lookup (#4046)**
* fix(github): resolve the PR's own repo in the provenance check and the required-check lookup

pr_provenance._collect_actions built its reviews and timeline paths from current_repo(), so vrg-finalize-pr <PR URL> run from a checkout of another repo checked the wrong PR or 404'd. It now takes the repo and number from the PR itself through a new github.pr_repo_and_number helper, which update_branch (#3976) now shares. required_check_names no longer falls back to current_repo() when the PR's URL does not parse: it raises GitHubAPIError, which propagates past its warn-and-return-None handler rather than reading another repo's rules. Ref vergil-project/vergil-tooling#4013

* test(github): cover a missing token during the required-check rules lookup

The required-check lookup now has two guarded phases; cover the token error propagating from the second one too. Ref vergil-project/vergil-tooling#4013


## Features

- **shellcheck every *.sh file in the repository, not only scripts/ (#4042)**
The common shellcheck stage discovered shell files only under scripts/, so shell kept elsewhere (vergil-claude-plugin's hooks/, vergil-actions' step scripts, repos' tests/) was never linted. Add every *.sh file git lists (tracked or untracked, gitignored excluded) to the scripts/ scan. Ref #3830.

- **fetch the issue body and the epic's open tasks in vrg-merge-review-request (#4047)**
* feat(merge-review): fetch the issue body and the epic's open tasks in vrg-merge-review-request

The builder now reads the task's body from GitHub and derives the epic's open tasks from the task's native parent (an epic that is not ad-hoc: its open sub-issues, every page, less the task), so the agent under review no longer chooses what the reviewer is told the task is. --issue-body-file and --epic-tasks-file are removed; a failed or malformed fetch is a refusal. Ref #4041.

* test(merge-review): cover each fetch failing on its own in vrg-merge-review-request
