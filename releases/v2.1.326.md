# Release 2.1.326 (2026-11-18)

## Bug fixes

- **adopt the PR a failed gh pr create opened in mechanized, release and update-deps PRs (#4705)**
  The create-or-adopt handling vrg-submit-pr gained in #4696 moves into a shared lib/pr_create helper, used by submit and by the mechanized-PR block, release prepare, the back-merge bump and the dependency update. Each runs gh pr create once per attempt and, after a failed attempt, adopts the open PR from its branch into its base only when head branch, base, title and pushed head commit match; any other open PR fails loudly, naming it. An adopted dependency-update PR gets its label again, since gh applies it after the create. open_prs_for_head takes a repo for the mechanized flow. Refs #4699.
- **forward --output-format and --output-window to the chained vrg-finalize-pr (#4711)**
  When given, the progress flags now reach the vrg-finalize-pr that vrg-submit-pr chains, and the printed --no-finalize command, so both halves of one run render alike. Left out, both still auto-detect.
- **stop naming a fixed exit 1 in the settle summary (#4712)**
  vrg-finalize-pr decides its exit status after the settle pipeline (3, 4 or 5 from the settle and watch outcomes and any chained release), so the pipeline's summary named a wrong 'exit 1'. The settle pipeline now passes failure_exit=None, as vrg-submit-pr does, and its summary names no status.

## Features

- **show the final report as one PR table like vrg-repo-status (#4713)**
  The report's Merged/Not merged groups of bare URLs become one table: PR, BRANCH, TYPE, OUTCOME and TITLE, typed and laid out as vrg-repo-status's PR tables are, through a new shared lib/text_table. The watch now carries each PR's title, head branch and labels from its existing gh pr view, so the table costs no extra call. Reasons, next steps and provenance violations print as notes under the table; empty groups no longer print (none).
- **run the per-PR submit as a step rollup like vrg-release (#4714)**
  * feat(submit-pr): run the per-PR submit as a progress rollup, one stage per PR

  After the confirmation, vrg-submit-pr now opens its PRs through the shared progress rollup that vrg-release uses: one stage per PR, named after its branch, covering the batch recheck, push, origin-tip check, open or adopt, submission record, provenance check and auto-merge. Each stage ends on one line with its mark, duration and outcome (for example 'PR #123 auto-merge on (squash, pinned to <sha12>)'), the steps' output goes to .vergil/vrg-submit-pr-<stamp>.log in the main worktree, and the summary points at it. Previews, refusals, the confirmation and --dry-run stay plain; the chained vrg-finalize-pr and the post-rollup guidance are unchanged. A failed PR fails its stage and the next PR still runs; SubmitSummary and the exit codes are unchanged. An unexpected error or an interrupt stops the rollup and is raised after its summary. The progress library gains note() for an ok stage's status line, StageFailedError for a reason without a type prefix, and a failure_exit option so the summary does not claim an exit status the command decides later. vrg-submit-pr takes --output-format and --output-window.
