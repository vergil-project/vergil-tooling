# Release 2.1.356 (2026-11-28)

## Bug fixes

- **read the human's scope-change comment in submit's record read (#5389)**
  * test(merge-review): cover submit's record read taking a human scope change (#5387)

  * fix(merge-review): read the human's scope change in the record stream (#5387)

  The merge-review record read narrowed the trust stream to the agent role, so submit's gate reader judged the human's vrg-scope-change comment not-accepted and printed it as ignored. The record read now takes the human and agent comments as vrg-issue-read does, carries each comment's judged role, and keeps only an agent-posted, unedited comment as a record.

- **raise the batch ceiling to 20 (#5339)**
  Raise MAX_BATCH from 8 to 20 (epic vergil-project/.github#1672, spec 5.2) and update every statement of the old limit: the batch_rules and vrg-pr-workflow help text, the vrg-submit-pr docstring, the worktree convention, and the submit-pr, finalize-pr, cli-tools-overview, github-issues and git-workflow docs. The size guideline's word 'small' is dropped where it described batches. Tests cover twenty allowed and twenty-one refused.
- **keep a develop PR's closing lines on pr edit (#5343)**
  A pr edit that sets the body of a PR into develop (or moves it there with --base) is refused, for every identity, when the multiset of its Ref lines and closing-keyword references (Closes, Fixes, Resolves) differs from the current body's. The current base and body are read with gh pr view; a failed read, or a body that cannot be read, refuses the edit. Edits on other bases, title-only edits and --help pass without a read. Spec 5.2 of epic vergil-project/.github#1672.
