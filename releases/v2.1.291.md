
# Release 2.1.291 (2026-11-09)

## Bug fixes

- **make a plugin enabled from an undeclared marketplace a fatal refresh error (#4101)**
* fix(marketplace): refuse a plugin enabled from a marketplace settings.json does not declare

The refresh updates only the marketplaces it adds, so a plugin enabled from any other marketplace was updated from a catalog nobody refreshed and could stay stale while the refresh reported success. settings.json now has to declare every marketplace it enables a plugin from (claude-plugins-official aside, which the refresh adds and updates itself). An undeclared one is a MarketplaceError naming each plugin and its marketplace, raised before any claude call by the refresh and by the vrg-vm update pre-copy check alike.

Ref vergil-project/vergil-tooling#3995

* fix(marketplace): stop the refresh on an enabled install from a marketplace settings.json does not declare

claude plugin list --json can report an install as enabled that settings.json does not enable, such as one a project's own settings enable. The refresh updated every enabled install, so one from a marketplace the refresh never refreshed was updated from a stale catalog. Per the N1 ruling, after the listing such an install is now a fatal MarketplaceError naming each install and its marketplace, raised before any plugin update, so the refresh exits non-zero. claude-plugins-official counts only when the refresh refreshed it.

Ref vergil-project/vergil-tooling#3995

## Features

- **keep the hook guard shim current with an audit content check and a fleet-sync target (#4110)**
* feat(audit): report a stale or edited hook guard shim, not only a missing one

_check_hook_guard_shim now compares .claude/hooks/guard.sh byte for byte with the packaged shim, which fails closed, and reports drift or an unreadable file as a diff item. The packaged shim is read through one render function in repo_config, which repo_init also uses. Ref #4109

* feat(fleet-sync): add a hook-guard-shim target for the managed .claude/hooks/guard.sh

Add vrg-hook-guard-shim-sync, a single-repo applicator that checks or atomically writes the packaged hook guard shim, mode 0755, using the audit's byte comparison plus an execute-bit check, so --check drifts exactly when --write changes the file. An unreadable shim exits 2 so the sweep records an error. Register it as a console script, add the hook-guard-shim target to vrg-fleet-sync, and document both alongside the audit check. Ref #4109
