
# Release 2.1.274 (2026-10-27)

## Bug fixes

- **count-aware plurals in the held note and the show refusal (#3739)**
Choose the noun and verb from the advisory count instead of printing advisory(ies): 1 advisory still tracks / 2 advisories still track, and advisory ... does not exist / advisories ... do not exist. Tests cover singular and plural of both messages. Refs vergil-project/vergil-tooling#3736

- **count-free wording for the held note's retarget hint (#3744)**
One advisory can be retargeted to several tasks, so there is no count to pick a noun from. The planning hold note now says 'the task or tasks that fix it' instead of 'its fix task(s)'. Refs #3738.

## Features

- **several advisories per issue in the library, the sweep and show (#3734)**
An issue may now name any number of advisories, one Security advisory:
line each (epic vergil-project/.github#573, Task 1):

- parse_advisory_refs returns every GHSA ID a body names, in order,
  without repeats; parse_advisory_ref stays (first entry) until Task 2
  moves intake routing and the planning hold.
- unmark_issue acts when any line names the advisory, removes that line
  only, and drops the security label only with the last line.
- SecurityIssue carries ghsa_ids; classify checks every line both ways,
  and retarget's dropped-issue scan is a membership test.
- vrg-security-record show <issue> prints every pair in body order, and
  refuses, printing nothing, if any named advisory is missing.

Refs vergil-project/vergil-tooling#3730

- **routing and the planning hold over every advisory (#3735)**
vrg-intake-route transfer and recreate now retarget every advisory an item names, in body order, and a failure names each advisory still pending with its recovery command. A split of an item naming several advisories is refused before any change. vrg-queue planning holds an item while any advisory it names still tracks it. parse_advisory_ref is removed now that no caller remains.
