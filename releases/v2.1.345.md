# Release 2.1.345 (2026-11-24)

## Bug fixes

- **allow the agent's own merge close in provenance and list CD runs with its token (#5144)**
  * fix(provenance): allow the closing that accompanies the user agent's merge of its own PR

  GitHub records a closed event, by the merging actor, for every merge, so every agent self-merge was flagged as a provenance violation. A close is now part of the merge when the PR merged once, the close is the first one after the merge in timeline order, at the merge's second, and by the merge's actor; any other close stays a violation. The recorded timeline of vergil-fixture-python-lib PR #87 is the fixture. Ref #5140.

  * fix(finalize): list the CD runs with the current identity's token and fail loudly when it cannot

  The CD check ran raw gh run list and gh run view with no GH_TOKEN, so an agent had no auth and the CD state was reported as unknown. Both now run through lib/github's authenticated path, as the App in agent mode (the named repo's owner for an explicit repo). A listing that fails in a repo that declares CD, no credentials included, is an error naming its cause that fails the cd-check stage with exit 1, never 4, and the report shows CD: error (<cause>). The finalize reference documents this and the merge-close provenance rule. Ref #5140.

  * fix(finalize): read the CD runs through the runner the trust guard resolves

  Inline the run_tolerating calls with their argv so the trust guard resolves them, keep subprocess a type-only import, and cover a merge close with no actor. Ref #5140.
