# Release 2.1.342 (2026-11-24)

## Bug fixes

- **show each VM's actual Lima disk size in list (#5031)**
  vrg-vm list's DISK column showed the configured size, so it could not confirm a disk change. It now reads the disk byte count limactl list --json reports for each instance, shows the configured size only for a VM not yet created, and marks a disk that differs from its configured size as <actual>≠<configured>. The column widens to fit the marked value.
- **count native blocked-by relationships as blockers in the task views (#5114)**
  * fix(queue): count native blocked-by relationships as blockers in the task views

  vrg-queue adhoc and hoshin read only body Blocked-by: lines, so a task held by native GitHub blocked-by relationships was listed ready. The sub-issue listing now reads each child's blockedBy list in the same GraphQL query (a reflink-fallback child's is read on its own), a blocker in any org counts, and a list that cannot be read in full fails the view rather than show the task ready. Ref #5094.

  * fixup! fix(queue): count native blocked-by relationships as blockers in the task views

  * fix(queue): check native blocker lists only of the children a view keeps

  A closed child, or one the --repo filter drops, no longer fails vrg-queue adhoc or hoshin over a blocked-by list it never needed. Merge review R1 of #5094.

  * fixup! fix(queue): check native blocker lists only of the children a view keeps

- **clear disk-only drift on a VM already at its configured size (#5118)**
  grow-disk re-stamped a dedicated VM's fingerprint only after a grow it ran itself, so a VM grown by hand, or one whose re-stamp failed after a grow, kept reading NEEDS-REBUILD while grow-disk printed nothing to grow. A running dedicated VM at its configured size now gets the same check: its old size is not recorded, but Lima never shrinks a disk, so each whole-GiB size below the current one is tried, and only a stamp that matches the current spec with the disk at one of them is re-stamped. Any other drift stays for a rebuild; a stopped VM is refused with the command to start it. Ref #5104.
- **remove the protected-change approval and the human skips of merge review (#5119)**
  By the human's ruling on epic vergil-project/.github#1384, the protected-change approval goes from submit, the finalize watch, the audit and vrg-ruling, and lib/protected_paths.py is removed. The human's two submit-time skips, --human-only and --override-merge-review (with the override comment it posted), go too, so merge-review coverage is met only by a merge-review record or a human-approved merge-review exemption, on every submission. The removed flags are refused by name. recorded_by stays an add-only hint for the watch.
- **count native blocked-by relationships when deciding a child is runnable (#5109)**
  child_status and operational_status read each open child's native blocked-by list with child_states_with_blockers (a reflink child's with native_blockers_of) and keep a child blocked while any native or Blocked-by blocker is open. An incomplete native read raises NativeBlockersReadError, never runnable. The dataclass fields are unchanged.
- **count a native blocked-by link to an open deployment task in the batch rules (#5110)**
  The no-open-deployment-blocker hard rule (batch-start, report-ready, submit) now also reads the issue's native blocked-by links with native_blockers_of and refuses on an open deployment blocker, in any repo or org. An incomplete native read refuses the batch, never allows it.
- **pass the App keys by name for repos outside vergil-project (#5108)**
  GitHub passes secrets: inherit only to a reusable workflow in the caller's own organization or enterprise, so the generated App-key callers of a repo outside vergil-project passed nothing and failed for want of APP_CLIENT_ID. Those repos now pass APP_CLIENT_ID and APP_PRIVATE_KEY by name, plus CARGO_REGISTRY_TOKEN for a rust release job; vergil-project repos keep secrets: inherit. The ci-architecture and consuming-repo-setup guides say which shape applies where.

## Features

- **add vrg-state-dir to create and check a task's state directory (#5105)**
  * feat(state-dir): add vrg-state-dir, which creates and checks a task's state directory

  vrg-state-dir --kind operational|issue-implement|upstream-report --issue owner/name#N --ensure checks build/.vergil-state/<kind>/<N>/ in the main clone level by level (each level a real directory at mode 700, absent levels created mode 700), refuses a symlink, a non-directory or a wrong mode, and prints the path. It reuses the checks vrg-merge-review-request --ensure-dir makes, through a new ensure_task_dir in lib/merge_review/state.py, and the same clone-is-issue-repo refusal. Ref #5027

  * fix(state-dir): run vrg-state-dir as a module and cover its git-failure path

- **add grow-disk to grow a Lima VM's disk in place (#5030)**
  vrg-vm had no way to grow an existing VM's disk. grow-disk automates the manual steps of vergil-vm#427: it stops the VM, sets the size with limactl edit --disk, starts it again (Lima 1.1+ grows the image and cloud-init fills it on boot) and re-injects credentials. It refuses a configured size below the disk, since Lima never shrinks one, checks that Lima reports the new size and prints the root filesystem size. A dedicated VM whose only spec drift was its disk has its fingerprint re-stamped, so list stops showing NEEDS-REBUILD; any other drift is left for a rebuild.
- **record why a stage was skipped and recognise skip records in vrg-ci-evidence (#5107)**
  * feat(validate): record why vrg-validate skipped a stage in its run record

  A stage skipped because the repo is not bootstrapped now carries a skip object (reason not-bootstrapped, the language and the missing manifests), so CI evidence staging can read the reason instead of repeating the manifest and source tests. A run that skips nothing keeps the record's shape. Ref #5034.

  * feat(ci-evidence): recognise not-bootstrapped skip records and record the gate's legs as skipped

  vrg-ci-evidence now reads each <gate>-not-bootstrapped-<version>.json (quality-<gate>-... for a quality leg) that vergil-actions#1294 stages as a skip record, refuses a malformed one or one not of the validated head, and lists the skipped legs under the gate's new manifest field skipped. Ref #5034.

  * fixup! feat(ci-evidence): recognise not-bootstrapped skip records and record the gate's legs as skipped

- **a daily audit of agent merges (#5111)**
  * feat(audit): a daily audit of agent merges

  Add vrg-agent-audit (lib/agent_audit.py): from the vergil/agent-audit/{develop,main} markers, it checks every merge's merge and auto-merge actors and provenance and, for an agent-involved PR merged into develop, the shared gates and any approved file the merge changed. GateResult gains read_failure so the audit can tell a failed lookup from a broken rule. Ref vergil-project/vergil-tooling#4787.

  * test(audit): cover every failure path of the agent audit

- **re-check the gates on every new head (#5113)**
  * feat(finalize): re-check the gates on every new head

  The watch re-runs provenance and the shared gate evaluator at start-up and on each new head of an open PR, fetching develop and the head first and refusing a clone of another repo. Agent involvement reads the PR's GitHub actors and its ready state's recorded_by from the relay ref; recorded_by only ever adds involvement. A failing or unreadable re-check turns auto-merge off and ends the PR failed: gates. vrg-finalize-pr refuses --release for every agent identity before any watch or cleanup. Ref #4786.

  * fix(finalize): re-check a new head of a PR that ended on its checks

  A PR that ended failed: CI or failed: cancelled keeps its auto-merge on and is re-read while the watch goes on; a new head of it now gets the provenance and gates check like a pending PR's, and a failure turns auto-merge off and replaces its result. Ref #4786.

- **agents submit through the gates (#5112)**
  * feat(submit-pr): agents submit through the gates

  vrg-submit-pr lets the user agent submit in the modes report-ready drives (template and --all/--select) and refuses it with --release, in the CLI emergency mode, on the relay path and with the override; the audit agent is refused. Before any push or gh pr create, every submission runs the shared gate evaluator (agent_gates.evaluate) against a freshly fetched origin/develop when it is agent-involved. report-ready now records the identity that recorded the ready state as recorded_by, in the local file and the relay ref; a missing or unknown value counts as agent-involved, and a human re-run never replaces an agent's recording. The human gets --override-merge-review, a logged override keyed by the change fingerprint that never covers a protected file. vrg-gh's agent PR denials point at report-ready and vrg-submit-pr. Ref vergil-project/vergil-tooling#4785

  * feat(submit-pr): run the gates on every submission unless the human passes --human-only

  vrg-submit-pr now runs the protected-change and merge-review gates on every submission, whoever recorded the ready state. The human may skip both with --human-only <reason>, which applies only to a ready state recorded by the human and adds a line to the PR body's notes recording the skip and its reason. --human-only is refused under every agent identity (user, audit, automation), at argument time and again at the gate step, and cannot be combined with --override-merge-review. recorded_by stays in the ready state as a hint that can only make a change more agent-involved. Ref vergil-project/vergil-tooling#4785

  * style(submit-pr): format the --human-only gate test

- **create the agent audit markers (#5059)**
  A new step 10 creates vergil/agent-audit/develop and vergil/agent-audit/main at the tips of develop and main through agent_audit.init_markers, the audit's own create helper. A marker that exists is left untouched, so adopt never moves an audit's progress, and a failed read or create stops the run. GitHub Pages moves to step 11.
