
# Release 2.1.315 (2026-11-15)

## Bug fixes

- **retry pip-audit on transient network errors in the audit stage (#4434)**
A single PyPI read timeout failed the audit stage and with it a merge (#4364, #4365). The pip-audit call now gets up to three attempts, retried only when its stderr names a network or timeout error and never when it reports a vulnerability finding; exhausting the attempts fails the stage, naming the error and the attempt count. Ref #4423.

- **render the evidence README from the entries assembled (#4437)**
* fix(ci-evidence): render the evidence README from the entries assembled

The bundle README was a fixed text that always described gates/sbom/, which a release that builds no package does not have. Render it from the assembled tree instead: name each gate directory present, and say whether the archive holds gates/sbom/. Write it after the SBOM copy so it sees the final tree. Update the CI evidence convention guide to match.

## Features

- **add close, which closes a draft advisory with a reason posted on its issues (#4431)**
* feat(security-record): add close, which closes a draft advisory with a reason posted on its issues

vrg-security-record close GHSA --reason TEXT posts 'Security record <GHSA> closed: <reason>' on every issue the record tracks, then sets the advisory to closed. It refuses while any issue is open (sync would reopen it), for an external report or a non-draft state, and for a record with no issue to carry the comment. Ref vergil-project/vergil-tooling#4000.

* fixup! feat(security-record): add close, which closes a draft advisory with a reason posted on its issues

- **let the planning route take a follow-on brainstorm out of a development epic (#4432)**
* feat(intake-route): let the planning route take a follow-on brainstorm out of a development epic

A follow-on brainstorm (titled 'Follow-on brainstorm:') under a development epic can now be routed to planning: its parent is replaced in one call and the hand-off is recorded on the epic and the item. Every other development-epic task is still refused. Ref #4296.
