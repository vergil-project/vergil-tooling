
# Release 2.1.173 (2026-08-06)

## Bug fixes

- **reopen guest memory dir for writing before re-projection copy (#2592)**
A prior projection freezes the guest memory directory read-only via lock_projection (chmod -R a-w), and on a persistent guest disk that lock survives a VM rebuild. project_memory restored write per-file (chmod u+w {dest}) before each cat >, but that only reopens files that already exist. Creating a NEW host-added memory file needs write on the parent directory, which was still dr-xr-xr-x, so cat > failed with EACCES and aborted the whole cloud session on the first new file. Fold a chmod -R u+w of the guest memory subtree into the mkdir setup step so the directory is writable before the copy loop; lock_projection re-freezes it at the end as before. Refs #2591.
