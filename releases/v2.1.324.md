# Release 2.1.324 (2026-11-18)

## Bug fixes

- **withhold Node and npm host settings from containers, with a notice (#4675)**
- **show a submitted PR that cannot merge, with its reason (#4681)**
  * fix(repo-status): show an open PR mid-rebase and why a submitted PR cannot merge

  A detached worktree (a branch mid-rebase) skipped the PR lookup, so its open PR showed as '-'. The recovered branch's open PR is now looked up. Each open PR's merge state is read once with the new pr_await.standing_block, which reuses vrg-pr-await's judge and reasons; a PR that cannot merge shows 'merge failed: <reason>' in STATE beside any local state, with a note naming the failure instead of rebase instructions. Ref vergil-project/vergil-tooling#4678

  * fix(repo-status): read the merge state only for development worktrees

  Release and deps PRs are merged directly, never with auto-merge, so judging them by vrg-pr-await's reasons would always show auto_merge_off. Ref vergil-project/vergil-tooling#4678

- **clear a stale Rust coverage build when the toolchain changes (#4686)**
  The Rust TEST stage's 'cargo llvm-cov clean --workspace' removes only the workspace's artifacts as the current cargo lays them out, and cargo-llvm-cov passes llvm-cov every object under target/llvm-cov-target, so an earlier toolchain's debug/deps binaries reached the report and failed the 100% gate on correct code. vrg-validate now records rustc -vV, cargo -vV and cargo llvm-cov --version in .vergil/rust-coverage-toolchain.txt and runs the full 'cargo llvm-cov clean' when the record is missing or differs. A listing that contradicts the report's totals now names stale build output as the likely cause and the fix. Ref #4684

## Features

- **close an epic's planning issue from its docs PR (#4676)**
  * feat(pr-workflow): close an epic's planning issue from its docs PR

  When vrg-submit-pr opens the PR of an epic's documentation task, it now adds a 'Planning issue: Closes <ref>' line for the epic's planning issue, so merging the spec and plan also closes it. The planning issue is found from the epic body's Planning: line and confirmed by its latest trusted Docs task: marker. It is skipped, with the reason printed, when it is in another repo, closed, outside the planning queue, or still tracked by a security advisory. report-ready previews the result as planning_close. The line does not start with the keyword, so the PR is never read as a batch PR.

  * test(pr-workflow): cover the planning-close edge cases

- **honor time-boxed .npm-audit-exceptions in the TypeScript audit (#4685)**
  * feat(typescript): honor time-boxed .npm-audit-exceptions in the TypeScript audit

  npm audit has no ignore list, so a high advisory with no patched release failed the TypeScript audit gate in every repo that has the package. The new vrg-npm-audit-gate reads the npm audit report and the repo's .npm-audit-exceptions (one GHSA ID, exp:YYYY-MM-DD expiry, tracking issue and reason per line, as .trivyignore entries are reviewed), drops the advisories a live entry covers and lists them, and fails on any other advisory at high or critical. Expired, malformed, duplicate and over-90-day entries fail the gate by line; an unmatched entry is a warning. Issue #4682.

  * fixup! feat(typescript): honor time-boxed .npm-audit-exceptions in the TypeScript audit
