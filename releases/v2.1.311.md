
# Release 2.1.311 (2026-11-14)

## Bug fixes

- **check every workflow is registered and work around GitHub missing some (#4383)**
* fix(repo-init): check every workflow is registered and work around GitHub missing some

After step 8, vrg-github-repo-init compares the workflow files on the default branch with the workflows GitHub Actions registered. When some are missing it switches the default branch away and back (a workaround for an upstream GitHub bug), waits a bounded time, and stops naming any still missing. A resumed run checks too. Ref #4376.

* fixup! fix(repo-init): check every workflow is registered and work around GitHub missing some

- **run CodeQL for rust from the one CodeQL language set the ruleset uses (#4387)**
* fix(repo-init): run CodeQL for rust from the one CodeQL language set the ruleset uses

repo_init kept its own CodeQL language list, which omitted rust, so vrg-github-repo-init wrote run-codeql: false into a Rust repo's ci.yml while the CI-gates ruleset required security / codeql and CodeQL. Every PR stayed blocked with green checks. Both now read github_config.CODEQL_LANGUAGES. The csharp, javascript, swift and kotlin entries are dropped: none is a Vergil primary language, so they could never match. A test checks every primary language runs CodeQL exactly when the ruleset requires it. Ref #4381

* fixup! fix(repo-init): run CodeQL for rust from the one CodeQL language set the ruleset uses

- **skip the language stages, loudly, on a repo not bootstrapped yet (#4390)**
* fix(validate): skip the language stages, loudly, on a repo not bootstrapped yet

A Rust repo with no Cargo.toml failed vrg-validate's install stage, while the image warmup already skipped it as not bootstrapped. vrg-validate now uses the warmup's manifest table: when every manifest of the language is missing, the install, lint, typecheck, test and audit stages are recorded as warnings naming the missing files, and the common checks and custom validator still run. A partial bootstrap, or a Cargo.toml that cargo fetch cannot resolve, still fails. Ref #4384

* fix(validate): fail, not skip, a repo with sources but no manifest

Per the merge-review ruling on R1: a repo is judged not bootstrapped only when it has none of its language's manifests and no source files of its language either. A repo with sources but no manifest (a branch that deletes Cargo.toml, or adds Rust sources without one) now fails its install stage, naming the missing manifests and the first sources, instead of passing every language stage as a warning. Ref #4384

* test(validate): narrow the install-stage choices test for ty

* test(validate): pin that a Rust repo with no Cargo.toml never runs the doctest probe

The library-target probe added by #4378 runs cargo metadata, which fails with no Cargo.toml. On an unbootstrapped Rust repo the test stage is a skip, and on one with sources but no manifest the install stage stops the run, so the probe must never run on either. Ref #4384


## CI

- **move the nightly ops cron to the 01:xx UTC hour (#4386)**
GitHub's schedule events fire 7 to 9 hours late, landing the 06:xx UTC run in the US Eastern working morning. Move the hour to 01 UTC (minute stagger unchanged) in ops.yml and in render_ops_workflow, so new repos are born on the new hour. Ref #4380.


## Features

- **lint all targets with clippy, tests included (#4385)**
The Rust lint gate ran cargo clippy with no target flag, which checks only the library and binaries, so integration tests, #[cfg(test)] modules, examples and benches were never linted. Add --all-targets (--lib --bins --tests --benches --examples), pin the argv in the test, and state the scope in the Rust standards doc.

Ref vergil-project/vergil-tooling#4379

- **run rustdoc examples in the Rust test gate (#4388)**
* feat(rust): run rustdoc examples in the Rust test gate with cargo test --doc

cargo llvm-cov runs cargo test --tests, so no rustdoc example was ever built or run. The TEST check now runs cargo test --doc after the coverage command. cargo llvm-cov --doctests needs rustdoc's nightly-only -Z unstable-options --persist-doctests, which the stable dev image refuses. The 100% line gate is unchanged.
