# Release 2.1.325 (2026-11-18)

## Bug fixes

- **a check cancelled by a superseding CI run is not a failure (#4693)**
  * fix(finalize): a check cancelled by a superseding CI run is not a failure

  The shared check judging (finalize_watch.check_failures) now reads the head's Actions runs and leaves out a failed or cancelled check-run whose run a newer run of the same workflow superseded, even before the newer run registers any check-run. A cancelled check with no newer run holds the PR pending for a grace period, then ends it failed: cancelled (vrg-pr-await reason check_cancelled). The finalize watch re-reads a PR that ended on its checks, so a merged PR is reported merged. vrg-finalize-pr, vrg-pr-await and vrg-repo-status share the rule. Ref #4692.

  * fix(finalize): skip checks that are not required before reading their run link

  * fix(finalize): judge a check that failed after the snapshot on the next snapshot

- **adopt the PR a failed gh pr create opened instead of retrying it blindly (#4700)**
  * fix(submit): adopt the PR a failed gh pr create opened instead of retrying it blindly

  gh pr create now runs once per attempt. After a failed attempt, vrg-submit-pr looks for an open PR from the branch into the base and adopts it only when head branch, base, title and head commit match; any other open PR fails the submit, naming it. With none open, a transient error is retried with the shared backoff. The auto-merge mutation and the direct merge, both retried by the gh wrapper, now read the PR back before failing, so a write that landed is not reported as failed. Refs #4696.

  * fixup! fix(submit): adopt the PR a failed gh pr create opened instead of retrying it blindly

## Features

- **show the watch as a live, collapsing progress stage (#4698)**
  * feat(finalize): show the watch as a live, collapsing progress stage

  On a TTY the watch's status table is redrawn in place under a 'watch' stage that collapses to one line (e.g. '⚠ watch  3m12s — 4 merged, 1 failed'). Off a TTY the table is printed only when some PR's state changes, with a heartbeat line every five minutes. The watch and the settle phase share one run log, which keeps every changed table with a timestamp. Adds progress.status_block, progress.run_stage and run_pipeline(log=...). Ref #4694.

  * test(finalize-pr): pin the plain renderer in the watch-stage tests

  Under GitHub Actions detect_format() picks the gha renderer, so the watch-stage tests that assert plain-renderer output failed in CI. A fixture now removes GITHUB_ACTIONS for those tests, as test_progress.py does. Ref #4694

- **a provenance violation always fails; drop advisories and remove --allow-provenance-violation (#4701)**
  * feat(provenance): a provenance violation always fails: drop advisories and remove --allow-provenance-violation

  The provenance check now has two outcomes, allowed or a violation. The audit-approval advisory is gone (the audit identity is unused, so it never fired), and the audit identity's forbidden actions are kept. --allow-provenance-violation is removed from vrg-submit-pr and vrg-finalize-pr; passing it is refused by name before any side effect, naming the new rule. Docs and the permission-model spec record the removal and why. Refs #4695.

  * fixup! feat(provenance): a provenance violation always fails: drop advisories and remove --allow-provenance-violation
