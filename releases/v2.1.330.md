# Release 2.1.330 (2026-11-20)

## Bug fixes

- **give the shared base Lima VM the base footprint's disk, CPUs and memory (#4810)**
  The shared base path passed the identity's own cpus/memory/disk to create_vm, which are None when unset, so Lima fell back to the template's 50GiB disk while vrg-vm list reported the base footprint's 100GiB. Pass the composed base footprint instead, as the dedicated path already does.
- **compose a named Lima instance's overlay when vrg-vm list checks its spec (#4806)**
  Create and rebuild compose a dedicated VM's spec with its named-instance overlay and stamp that fingerprint, but list composed it without the overlay. An instance whose overlay sets a value (mq-resiliency-lab's local instance sets disk = 300GiB) therefore read NEEDS-REBUILD right after a rebuild, and its DISK column showed the base 100GiB; #4791 putting disk into the fingerprint is what exposed it. List now composes with the instance name it reads from the instance's sidecar, and a named instance the repo no longer declares is listed as orphaned instead of failing the composition.
- **write consumer-refresh's commands, output and exit status to the release log (#4819)**
  * fix(release): write consumer-refresh's commands, output and exit status to the release log

- **move an advisory to its fix's org on a cross-org retarget (#4816)**
  * feat(security-record): move an advisory to its fix's org on a cross-org retarget

  When every --to of a retarget is in another org, retarget copies the advisory to that org's .github with a Moved from: line, hands it to the fix tasks, writes Moved to: on the original, unmarks the dropped issues and closes it. A re-run reuses only a single draft, non-external copy carrying the exact line; --to spanning orgs is refused. The sync treats a moved advisory as terminal and checks its copy. Ref vergil-project/vergil-tooling#4805

  * fix(security-record): refuse to move an advisory that is itself a move's copy

  A copy moved on to a third org would leave its original naming an advisory that tracks nothing, which sync reports as broken for good. The refusal names the one-copy-per-org way out. Ref vergil-project/vergil-tooling#4805

  * fix(security-record): refuse the move lines in every advisory-text writer

  create now refuses a body file, details file or summary holding a Moved from: or Moved to: line, with --resume too, through the same check note uses (refuse_move_lines), so only the move writes those lines. The _move docstring now lists the copy-of-a-copy refusal. Ref #4805.
