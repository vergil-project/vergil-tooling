# Release 2.1.334 (2026-11-22)

## Bug fixes

- **restore the cast import that the merge of #4879 and #4880 dropped (#4883)**
- **order open releases by semantic version, not as strings (#4885)**
  The fresh-start open-release refusal and the --resume ambiguity message sorted release versions as strings, listing 2.0.10 before 2.0.9. Both now sort with the existing host_versions.compare comparator. Ref #4877
- **refuse a resume whose release branch is missing (#4888)**
  * fix(release): refuse a resume whose release branch is missing

  A resume that adopts the release worktree now refuses, naming release/<version>, when that branch exists neither locally nor on origin, instead of cutting a new branch from develop. A fresh run still creates the branch off develop. Ref #4886.

  * style(release): format the missing-branch resume test

- **let a resume past merge-release run without the deleted release branch (#4892)**
  * fix(release): let a resume past merge-release run without the deleted release branch

  Once the release PR merges, GitHub deletes release/<version>, so a resume whose first undone stage is confirm-main, back-merge-bump or teardown-worktree no longer adopts the branch. It reuses the release worktree if it is still there (refusing a path that is not a git worktree), creates one detached at develop when back-merge-bump still has to run, and otherwise runs from the root checkout, where teardown-worktree does nothing and is recorded done. The #4886 refusal stays for prepare and merge-release. Ref #4889

  * fix(release): format the post-merge tests and flatten the resume worktree bullets

- **record the release's target version bump so a resume never drops it (#4909)**
  The state block records version_bump, the bump prepare applies to reach the target version, at the tracking issue's creation. A resume before merge-release holds the release branch's committed VERSION to the target: it completes a bump prepare stopped before, and refuses any other VERSION or an uncommitted version change, naming both versions. prepare refuses a bump that misses the target and an existing release PR while the bump is pending. Ref #4899.
