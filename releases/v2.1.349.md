# Release 2.1.349 (2026-11-25)

## Bug fixes

- **move a task between epics in one atomic re-parent (#5184)**
- **confirm a successful run rerun (#5175)**
  gh prints its Requested rerun line only when its stdout is a terminal, and vrg-gh captures gh's output to replay it, so a successful vrg-gh run rerun printed nothing and looked the same as a no-op. The wrapper now prints the confirmation itself on success, naming the run or job only when its ID is all digits.
- **report branches named like a rolling tag as config drift (#5200)**
  * fix(github-config): report branches named like a rolling tag as config drift

  The config audit lists the repo's branches matching the rolling-tag pattern and reports each one as drift; apply leaves them for a human and exits 1. Fixes the security record tracked by #3980 (GHSA-3h2p-fm65-f2v3, GHSA-7g54-j55j-f4mh).

  * fixup! fix(github-config): report branches named like a rolling tag as config drift

  * docs(github-config): list the rolling-tag branch case among the apply and update exit-1 causes

- **retry dnf metadata refreshes through the Pages cache window after an index publish (#5211)**
  * fix(package): retry dnf metadata refreshes through the Pages cache window after an index publish

  For up to 600s after a package index publish, GitHub Pages can serve repomd.xml and repomd.xml.asc from different publishes, and dnf with repo_gpgcheck=1 fails the signature check. repo_setup.dnf_refresh retries 'dnf -y makecache --refresh --repo <repo>' on that failure alone, over 750s, and fails loudly with dnf's output when the window is exhausted. It is used by the bootstrap (the installed-keyring refresh and a new refresh before the keyring install) and by install-test before the artifact install. The match comes from real dnf output captured on RHEL 9 and RHEL 10, recorded under tests/vergil_tooling/fixtures/dnf/. Refs #4663

  * fixup! fix(package): retry dnf metadata refreshes through the Pages cache window after an index publish

  * fix(package): refresh the vergil repo through the cache window before the python builder's RHEL runtime install

  On a fresh bootstrap the runtime dnf install was the first read of the permanent vergil repo's metadata, exposed to the Pages cache race with no retry. Run repo_setup.dnf_refresh for it first, as the deb branch runs its scoped apt-get update (human ruling N0.1 on #4663).

- **accept any git ref of vergil-tooling (branch, tag or commit) (#5195)**
  * feat(tooling-install): accept any git ref of vergil-tooling: branch, tag or commit

  vrg-tooling-install now takes a branch, a non-release tag or a full commit SHA besides vX.Y and vX.Y.Z.
