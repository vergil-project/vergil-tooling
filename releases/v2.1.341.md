# Release 2.1.341 (2026-11-24)

## Bug fixes

- **exit 2 from check on auth, installation, token or gh-version errors (#5079)**
  A missing App installation, a failed App login, a missing token or a gh older than the minimum escaped check's handler and reached cli_main, which exits 1, the code for findings. check and app-secrets now share one handler for these setup errors, which exits 2 with a message naming the cause. Refs #5079.
- **merge the release PR into main with the human's ruleset bypass (#5099)**
  * fix(release): merge the release PR into main with the human's ruleset bypass

  The Main updates ruleset lets only its bypass actor, the repository admin role, update main, and a plain gh pr merge does not ask for the bypass, so every release PR sat BLOCKED with green checks until pr_merge timed out. The merge-release stage now passes --admin, pinned with --match-head-commit to a head whose checks, required checks and review decision pr_merge re-reads just before the merge. It refuses any identity but the human's and any PR whose base is not main, and a refused bypass stops with a message naming the ruleset instead of polling. No other merge changes.

  * fixup! fix(release): merge the release PR into main with the human's ruleset bypass

  * fix(release): refuse the ruleset bypass when the required checks cannot be read

  Merge review R1: with no required set the bypassed merge could skip a required check that has not registered yet.

## Features

- **one evaluator for approvals and merge-review coverage (#5097)**
  * feat(gates): one evaluator for approvals and merge-review coverage

  Add lib/agent_gates.py, the shared evaluator submit, the finalize watch and the daily audit will call (epic vergil-project/.github#1384, Task 8): evaluate() applies the protected-change approval rule and the merge-review coverage rule (record, exemption or human override, by change fingerprint; per-commit for a batch), failing closed on every lookup error and on a change with no task issue. It also adds the human override reader (overrides) and agent_involved(), the one shared test of whether the rules apply. record.py exposes its batch commit helpers for reuse.

  * style(gates): format the gate evaluator and cover a repeated task issue

- **lint docs/security/ in vrg-validate's markdownlint scope (#5012)**
  Add docs/security/**/*.md to _find_markdown_files, so the Scorecard snapshots and other security records are linted against the bundled config, and docs-links reads them too. The rest of docs/ stays out of scope. Every org repo's docs/security/*.md at origin/develop lints clean against the bundled config. Refs #5012.
