# Release 2.1.347 (2026-11-25)

## Bug fixes

- **resume a merged release by re-running only its failed CD run (#5170)**
  * fix(release): resume a merged release by re-running only its failed CD run (#5153)

  Once the release PR has merged, a re-run of its CI fails the version-bump check (head and main at the same version), so the resume's CI re-run before the CD re-run could never pass and replaced the attempt that had passed. confirm-main's recovery now re-runs only the recorded failed CD release run. It still checks that the release PR's head has a CI attempt that passed, accepting the newest passing attempt even when a later re-run of the same run failed (ci_evidence.select_passed_attempt), and names that attempt in the log. The release is still judged on the CD run's release job, its evidence gate included.

  * fixup! fix(release): resume a merged release by re-running only its failed CD run (#5153)

  * fix(ci-evidence): harvest an earlier passing CI attempt as that attempt's own (#5153)

  Per the merge-review ruling on R1: the CD evidence harvest now selects the newest passing attempt of the release PR's CI run, the same rule as the resume's pre-check (select_passed_attempt, which replaces select_ci_run). When that attempt is not the run's latest, the harvest reads that attempt only: the workflow check conclusions come from its attempt-jobs list, the GitHub Advanced Security scanner checks are the newest that started inside its window (first job start to the next attempt's start), and only evidence artifacts created in that window are consumed. A required check or artifact that cannot be tied to the attempt raises AttemptScopeError, naming it. A latest attempt that passed is harvested as before; a failed latest attempt never counts as passing.

  * fixup! fix(ci-evidence): harvest an earlier passing CI attempt as that attempt's own (#5153)
