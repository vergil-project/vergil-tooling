- **add an in-process App token source that mints, renews and revokes repo-scoped tokens (#4520)**
* feat(automation): add the App token source that mints, renews and revokes repo-scoped tokens in-process

lib/app_token.py signs the App JWT in-process with cryptography (RS256), checks the key's App slug and each new token's viewer login, mints installation tokens limited to one repo and the given permissions, renews them once older than renew_after_secs (1800 by default) and revokes the replaced token at once and the current one on close. Revocation retries only network errors and 5xx, and a 401 on a retry counts as already revoked. read_credentials_from_env pops VRG_AUTOMATION_CLIENT_ID and VRG_AUTOMATION_PRIVATE_KEY. Adds the cryptography dependency.

- **route a registered token source through every gh and git call (#4530)**
* feat(automation): route a registered token source through every gh and git call

A token source registered with github.set_token_source (or the github.token_source context manager) supplies the token for every gh and git call. _gh_env and _git_env take the source's current token first, and every retrying caller (_run_with_retry, run_tolerating, the binary GET, git's retry loop) rebuilds its environment for each attempt through an env factory, so a renewal reaches the next call of a long wait_for_checks poll and a retry after HTTP 401 never repeats an expired token. Registering or using a source refuses while VRG_APP_ID or VRG_PRIVATE_KEY_PATH is set. With no source registered, every call is unchanged. Epic vergil-project/.github#1168, Task 2. Refs #4496.

* fixup! feat(automation): route a registered token source through every gh and git call

- **add publish, the CLI modes and the path-fenced self-merging PR (#4497) (#4531)**
vrg-upstream-refresh gains its publish half and its prepare, publish and combined modes. Publish holds the automation App's key, mints repo-scoped tokens through the token source, applies prepare's patch on the recorded develop commit in its own clone, computes the touched set from that clone, checks the path fence with rules from the develop tip, commits as the App's bot and waits through open_sync_pr with a 7200-second deadline from its own start. The combined mode is a human's local run and is refused under Actions; --dry-run (with --rules-from) is the one mode agents may run. Exit codes 0, 1 and 2, with usage errors mapped to 1. open_sync_pr takes a caller deadline and logs what it closed, opened and how the wait ended. The upstream-refresh, dependency-update and CLI overview pages, the reference index and the README now describe the new flow.
