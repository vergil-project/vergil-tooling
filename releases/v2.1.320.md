
# Release 2.1.320 (2026-11-17)

## Bug fixes

- **keep Vergil-managed files out of LINT's Prettier check (#4544)**
* fix(typescript): keep Vergil-managed files out of LINT's Prettier check

Prettier's check in TypeScript LINT flagged CLAUDE.md, .claude/settings.json and ops.yml in a newly created repo, files the repo cannot reformat because the fleet sync writes them. LINT now passes one !<path> pattern per file in repo_config.managed_paths, the files the config audit holds to Vergil's content, so a file Vergil starts to manage is left out with them. Ref #4541.

* fixup! fix(typescript): keep Vergil-managed files out of LINT's Prettier check

- **name both rules in the whole-file diff refusal of a version and hash line rule (#4545)**
A line rule with both version and hash groups needs the whole-file diff for the no-downgrade rule and the hash rule, so the refusal names both rather than only the no-downgrade rule.

## Features

- **let a line rule mark hash lines that change only with their block's version (#4540)**
A line rule may carry a (?P<hash>...) or (?P<hash_<suffix>>...) group. An existing hash line whose hash changes is refused unless a version of the same block (same anchor, or the whole file with no anchor group) changes in the same patch. A first-time hash pin is allowed. Under an anchored rule, a hash line removed from a block that stays is refused, so it cannot be moved to a new identity. A rule with no hash group behaves exactly as before. Ref vergil-project/vergil-tooling#4539
