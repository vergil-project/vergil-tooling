# Release 2.1.331 (2026-11-20)

## Bug fixes

- **run consumer-refresh when only update-deps failed (#4829)**
  update-deps prepares the next develop version, so its failure leaves the published release valid. consumer-refresh now skips only for a failed stage the release depends on; the update-deps failure is still reported and still ends the run with exit 1. Ref #4828.

## Chores

- **land 2.1.331 dependency update with a bounded retry for the real-gpg test (#4831)**
  * chore(deps): uv lock --upgrade

  * test(package): retry the real-gpg sign step once on the gpg-agent Bad passphrase race

  test_real_gpg_round_trip failed once in an xdist worker with gpg-agent refusing the correct loopback passphrase. The investigation could not reproduce it or prove a mechanism in our code, so the test now retries a sign step once, only on Bad passphrase, with a GpgAgentBadPassphraseRace warning naming the race; a second failure fails the test. sign.py is unchanged. Ref #4825.

## Features

- **stop requiring the develop-vX.Y.Z tag (#4826)**
  * feat(release): stop requiring the develop-vX.Y.Z tag

  vrg-release no longer checks for or reports the develop-v<version> tag, which nothing has used since the changelog boundary moved to the merge base with the previous vX.Y.Z tag (#3805). git-cliff now labels the release v<version> and the bundled templates strip the v, so the changelog heading and release-notes title are unchanged; develop-v* tags stay ignored while old ones remain.

- **add vrg-tooling-install, a Python locked host install of an exact release (#4832)**
  * feat(release): install the Mac's vergil-tooling with vrg-tooling-install

  The consumer refresh ran an inline shell script, with a trap for cleanup, to reinstall the host tools locked to the release's uv.lock. vrg-tooling-install does the same in Python, naming each step that fails, and the consumer refresh now runs the installed copy. The guides document an unlocked bootstrap followed by vrg-tooling-install for a fresh host or a broken install. Refs #4827

  * refactor(release): ship vrg-tooling-install alone, leaving the consumer refresh to #4830

  Split per the ruling on #4827: the consumer refresh runs the Mac's installed vergil-tooling, so it can only switch to vrg-tooling-install once a release has installed the command. vergil.toml and the install guides go back to develop; the refresh and guide changes move to #4830. Also formats the new code and covers its two remaining error paths. Refs #4827
