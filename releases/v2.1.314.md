
# Release 2.1.314 (2026-11-15)

## Bug fixes

- **make an interrupted release always recoverable (#4420)**
The tracking issue is now created with its stage checklist in the creation body, so --resume can always adopt it. A fresh run adopts a local release branch an interrupted run left with nothing on it (never pushed, no commits beyond develop, clean worktree) instead of refusing it, and never deletes anything. --resume takes over a checklist-less issue from older tooling when its release branch exists. The releasing guide describes the recovery paths. Ref #4367

- **audit vergil-tooling's managed files against its in-tree templates when releasing it (#4421)**
vrg-release's audit stage checked vergil-tooling's managed files with the installed release's templates. vergil-tooling holds the master copies, and a template change updates its own managed files in the same PR, so after any template change the release audit reported drift that was not there (#4401 after v2.1.312). Releasing vergil-tooling now passes vrg-github-repo-config audit --in-tree-templates, which runs the managed-file checks of the develop clone with the clone's own source tree in a child process, refusing a package loaded from anywhere else. The GitHub-side audit and every other repo's release audit are unchanged. The self-repo test (pyproject names vergil-tooling) moves from container_cache to lib/self_repo so both callers share it. Refs #4414.

- **make back-merge-bump safe to re-run after a partial failure (#4422)**
* fix(release): make back-merge-bump safe to re-run after a partial failure

A resume after back-merge-bump failed part-way re-ran 'git checkout -b' on the post-release branch the earlier run had created, and failed. The stage now reuses that branch when it holds only its own work (at origin/main, with or without an uncommitted partial bump, or one bump commit, pushed or not) and refuses any other state loudly, naming the branch, without resetting anything. Ref #4415

* test(release): cover a bump commit whose VERSION disagrees with its subject

## Features

- **write junit.xml from the rust TEST gate with cargo llvm-cov nextest (#4418)**
* feat(rust): write junit.xml from the rust TEST gate with cargo llvm-cov nextest

The rust TEST gate now runs the tests once with cargo-nextest under cargo-llvm-cov, then gates on one coverage report from that run. A packaged nextest tool config (configs/rust/nextest.toml) defines a vergil profile that turns on JUnit; the command copies the report to junit.xml at the repo root. The 100% line gate, coverage.xml and --show-missing-lines are kept, and cargo test --doc still runs the doctests, which nextest does not. junit.xml joins RUST_REPORT_FILES.

Ref vergil-project/vergil-tooling#4395

## Refactoring
