
# Release 2.1.293 (2026-11-09)

## Bug fixes

- **fail package-index fast when the followed publish-index run failed (#4125)**
* fix(release): fail package-index fast when the followed publish-index run failed

The package-index stage followed the publish-index run that covers the release, but treated it as progress output only. When that run failed, the stage kept polling the Pages index for the full 1200s timeout, then reported a timeout that pointed at the index rather than the failed run.

Now, when a followed run concludes failure, timed_out or startup_failure, the stage checks the index once more and looks for a newer index run to follow. If the index still lacks the release and there is no newer run, it fails at once, naming the run and its conclusion. A newer run is still followed, and a failure to list runs still falls back to plain polling, so the index poll stays the only check that passes the stage.
