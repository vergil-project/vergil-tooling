
# Release 2.1.299 (2026-11-10)

## Bug fixes

- **select index releases before downloading and verifying them (#4174)**
* fix(package-index): select index releases before downloading and verifying them

One paginated gh api release listing per product gives the packaged stable tags and their asset names. retention.select_tags picks the newest keep releases in each of the newest lines lines, and collect downloads only those. build_site now runs collect, drop_retired, verify, then indexes. The dependency closure, duplicate-bytes check and retire checks are removed with their tests (epic vergil-project/.github#1003, Task 1). Ref #4159.

* docs(package-index): stop describing the index's removed duplicate-bytes refusal

Merge review R1: the re-publish check docs, the releasing guide and the preflight docstring still said the index refuses a same-identity, different-bytes duplicate. Ref #4159.

* docs(package-index): give check_unpublished's real reason, not the removed index refusal

The check_unpublished error message and the published() docstring still said the package index refuses same-identity duplicates, which this branch removed. The message now gives the reason that holds: a rebuild would publish different bytes under an already-published version, a conflict apt and dnf cannot resolve. The check itself is unchanged.

* test(package-index): drop the assertion that the removed refusal wording is absent

- **name the repository in cached dev images so repositories stop evicting each other (#4177)**
A cached image is now tagged <base>:<base_tag>--<branch>--<repo>.<hash>, where repo is the clone's directory name, the same from each worktree. find_cached_image matches only the current repository's image, so the cache build's stale-image removal, vrg-container-cache status and clean, and vrg-finalize-pr's branch clean never touch another repository's image. Images in the old format (no repository) are never found again; plan_prune removes them unless a container uses them. Ref #4162.
