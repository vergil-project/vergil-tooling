
# Release 2.1.308 (2026-11-13)

## Bug fixes

- **record repo settings GitHub did not return as not checked, never as False (#4328)**
* fix(repo-config): record repo settings GitHub did not return as not checked, never as False

A repo-settings field missing from GET repos/{repo} (or null) is now recorded as not checked, as repo_settings.<field>, instead of defaulting to False or ''. A field of the wrong type, or a non-object response, raises. diff now exits 2 when any setting is not checked, as audit does; apply already refuses and writes nothing. Ref #4322.

* fix(repo-config): satisfy lint and typecheck for the strict repo-settings reads

- **name contents read and write in the not-checked line for a missing merge setting (#4329)**
GitHub's Get a repository docs say viewing merge-related settings needs contents:read and contents:write. A missing merge setting now says so; any other missing field keeps the generic wording, since the docs state no requirement for it. Ref #4326.

## Documentation

- **say the check for an apply is the human's apply exiting 0, not an agent's diff (#4332)**
The deployment-task scaffold and the github-issues standard told an agent to verify a human-run apply with diff, which exits 2 under the agent identity because the admin-scoped settings are not checked. They now say the check is the human's apply exiting 0 and that an agent's diff is informational only. config-audit.md gives each subcommand's exit codes as the code has them. Ref #4327.
