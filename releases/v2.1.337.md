# Release 2.1.337 (2026-11-23)

## Bug fixes

- **read release-notes and rebuild PRs through the trust layer (#5013)**
  * fix(trust): read release-notes and rebuild PRs through the trust layer

  The pending-release classification and issue list take a merged PR's title, head branch and labels only when it is a same-repo PR with a trusted author; any other merged PR is an untrusted row. The breached-release rebuild finds its release and back-merge PRs through trust.prs_for_branch, which now gives a merged PR's merge commit. Both reads leave the guard's pending list. Ref vergil-project/vergil-tooling#4986.

  * fixup! fix(trust): read release-notes and rebuild PRs through the trust layer

- **judge batch-check bodies and in-flight PRs through the trust layer (#5015)**
  * fix(trust): judge batch-check bodies and in-flight PRs through the trust layer

  batch-check reads the PR body only through trust.read_issue and fails on an untrusted one; the open-pr in-flight mark counts only same-repo PRs by trusted authors and the closing references the trust layer counts. Removes the three pending guard entries of this task.

  * test(trust): cover the in-flight page and missing-body refusals

- **read closing references through the trust layer in finalize and intake routing (#5014)**
  * fix(trust): judge closing references in finalize and intake routing

  Finalize closes only the closing references the trust layer counts, and intake routing's open-closing-PR guard holds a route only for a counted reference. A new trust-layer read of a PR by number (trust.read_pr_closing) feeds pending_release.trusted_closing_refs through lib/closing_refs.py. Ref vergil-project/vergil-tooling#4987.

  * fix(trust): cover the closing-reference edges and fix lint

- **read security-record issue bodies only through the trust layer (#5017)**
  * fix(security-record): read security-record issue bodies only through the trust layer

  The REST issue reads no longer take the body. mark_issue, unmark_issue, retarget's source tie and the security issue listing read each body through the trust layer: an untrusted body stops a mark, retarget or close before any write, and sync reports it and leaves the advisories tracking it unchanged. Removes this task's pending entries from the trust guard's exemptions (#4990).

  * test(security-record): cover the untrusted-body skip record lookup

  * fix(security-record): leave trust-error reporting to the cli_main boundary

  * docs(security-record): state the untrusted-body exit in sync help and the epic-audit reference

  The sync help, its --dry-run help and the module docstring now say an untrusted issue body is reported and exits 1, preview included; vrg-epic-audit's reference says its security-records preview exits 1 on one.

- **read the epic docs body and the planning hold's body through the trust layer (#5016)**
  * fix(trust): read the epic docs body and the planning hold's body through the trust layer

  vrg-epic-docs reads the body it rewrites with trust.read_issue(require_body=True), with one-line errors for an untrusted body, a trust-layer read failure and missing trusted authors. The planning view takes each item's Security advisory: lines from the trusted body it reads with the comments, and stops an item whose body is untrusted. Removes this task's pending trust-guard exemptions.

  * fixup! fix(trust): read the epic docs body and the planning hold's body through the trust layer

- **report vrg-version's expected errors in one line, not a traceback (#4484)**
  A missing VERSION, a VersionSyncError, a CargoVersionError or a failed git or lock command now prints vrg-version: <message> on stderr and exits 1. Any other exception keeps its traceback. The CLI reference no longer documents the uncaught error.
- **read package.json with the shared reader in vrg-version show (#4992)**
  A package.json that is not UTF-8 or not JSON now fails vrg-version show and the TypeScript pre-gate with the shared reader's message instead of a UnicodeDecodeError traceback, and the pre-gate lists it once. A missing package.json is reported once too, by the devDependencies check, as not found with its fix; the version and Prettier checks leave it to that check.

## Features

- **add vrg-ops-report for unattended job failures (#5024)**
  * feat(ops): add vrg-ops-report for unattended job failures

  Opens, comments on or records a recovery on a job's ops issue under the org's operations epic, reading every issue and comment through the trust layer (App-authored only), and never closes one. Ref vergil-project/vergil-tooling#4963.

  * fixup! feat(ops): add vrg-ops-report for unattended job failures

  * fix(ops): exit 2 on invalid vrg-ops-report argument values

- **refuse PRs for ops issues and keep the sweep off them (#5025)**
  An ops issue, under an org's operations epic, records that something broke and is closed by hand. epics.unbuildable_parent_kind replaces queue_item_kind in report-ready, vrg-submit-pr and the batch rules, so they refuse it as they refuse a queue item; the sweep's drift close skips it; and vrg-intake-route refuses every route out of the operations epic while still allowing a one-off into it. Task 2c of vergil-project/.github#1494.
- **allow the read-only remote, config, tag and variable queries (#5001)**
  vrg-git now allows remote [-v], remote get-url and remote show -n; config --get, --get-all, --get-regexp and --list; and tag in its list forms. Each is checked against an exact allowlist of its shape and flags, so every write form stays refused. vrg-gh allows variable list and get, reading an org's variables with that org's installation token; set and delete stay refused, as does gh api for the user identity.
- **allow vrg-gh release download for the agent identity (#5002)**
  Downloading a release asset changes nothing on GitHub, and doing it through the wrapper keeps the identity token and policy checks that a curl of the public asset URL skips. Validation runs that read a release's evidence bundle and manifest can now use it. The audit identity's allowlist is unchanged.
