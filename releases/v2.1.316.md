
# Release 2.1.316 (2026-11-16)

## Bug fixes

- **keep archives out of the orphan pass and flag misplaced ones (#4449)**
* fix(epics): keep archives out of the orphan pass and flag misplaced ones

Two archives in logical-minds-foundry ended up under intake epics. A legacy normalize run before #2821 failed to add the missing archive label, but its single gh issue edit still retitled the issue and removed epic, leaving an archive with neither label. The orphan pass judged top-level kinds by label only, so it attached each one to its home's intake epic, and re-attached them after a manual unlink.

The normalize now adds archive in its own edit before retitling, the orphan pass recognises an archive by its stamped title as well, and vrg-epic-audit reports an open archive that has a parent or lacks its archive label.

- **promote vX.Y only after the package index has the release (#4454)**
* fix(release): promote vX.Y only after the package index has the release

Move the promote stage after package-index, before close-finalize, so git-based and packaged installs of vX.Y agree from the moment the tag moves. When package-index defers, promote skips and vX.Y stays on the previous release; the deferral comment, the close-finalize outcome line, the publish-status error and the consumer-refresh hold name the pending vrg-promote, and the tracking issue stays open until the human promotes and closes it. Ref #4293

* fixup! fix(release): promote vX.Y only after the package index has the release

- **stop waiting for a required check whose producing job already failed (#4455)**
* fix(pr-merge): stop waiting for a required check a failed job will never upload

When every registered check has finished, a live check has failed and the only required checks still outstanding are unregistered, wait_for_checks returns at once instead of waiting out its deadline. The failed-checks abort then names each unregistered required check and, for a check a job's SARIF upload creates (Semgrep OSS, Trivy, CodeQL), the failed job that never uploaded it. Ref #4294.

* docs(finalize-pr): describe the fail-fast on an unregistered uploaded check


## Documentation

- **pin down the documentation-profile vergil.toml shape (#4453)**
* docs(vergil-toml): pin down the documentation-profile vergil.toml shape and what each key drives

Inventory of every vergil.toml key an org .github profile repo sets, traced through vergil-tooling and vergil-actions. Documents the canonical shape, names the two dead keys to leave out ([project].primary-language = "none" and [ci].versions) and notes that the [ci] table is required. Ref #4106

* docs(vergil-toml): say that repo-init --adopt keeps a drifted profile's values

Adopt re-renders vergil.toml from its current values, so it does not restore the documentation-profile shape by itself; a drifted profile repo is corrected by a change of its own. Merge review R1.

## Features

- **add note, which appends a dated private note to an advisory (#4450)**
* feat(security-record): add note, which appends a dated private note to an advisory

An append-only note subcommand reads the note from a file and adds it under a dated header, keeping the Tracking issue lines last. It prints IDs only and refuses a missing, external or published advisory. Ref #3998

* fixup! feat(security-record): add note, which appends a dated private note to an advisory

* fixup! feat(security-record): add note, which appends a dated private note to an advisory

- **run the semgrep gate's scan in vrg-validate and record every skipped PR gate (#4452)**
* feat(validate): run the semgrep gate's scan as a vrg-validate stage

vrg-validate now runs the scan PR CI's security / semgrep gate runs, with the same rulesets, fleet rule exclusions and suppression handling, so a semgrep finding fails local validation before the PR is opened. --check semgrep runs it alone. The scan's metrics are off and its SARIF goes to a temporary directory. The semgrep failure-message helper moves to lib/semgrep so vrg-semgrep-scan and the stage share it.

* docs(validate): record each PR CI gate local validation skips, with its decision

Lists every required PR CI check that vrg-validate does not run, with its run-locally or CI-only decision and reason, and names the four follow-ups (#4445, #4446, #4447, #4448). Addresses merge review finding R1 on #4003.

- **list the packages each dependency update changed in the PR body (#4456)**
Each built-in updater now itemizes the packages it moved, from a machine-readable source: python diffs the parsed uv.lock before and after the upgrade, vergil records the version and runtime pin it bumped, and images records each tag it bumped. The PR body gains a Package changes section with a per-updater count and a From/To table; the existing Updated lines are unchanged. The repo hook is shown as not itemized. Ref #4295
