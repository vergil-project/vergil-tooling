# Release 2.1.352 (2026-11-27)

## Bug fixes

- **wait for a CD run by reading it, and classify a failed read, in every release and finalize wait (#5302)**
  * fix(release): wait for a CD run's attempt by reading it, not by gh run watch's exit status

  A resume failed confirm-main because gh run watch exited 1 while the re-run's attempt was still in progress (#5174). The release now re-reads the run with gh run view until the attempt it waits for is completed, retries transient, 404 and malformed reads with back-off, and fails only on the run's own result, a persistent or non-transient read failure, or an attempt still going at $VRG_CD_TIMEOUT, naming which. The dead check_status mode and the streaming gh run watch wrapper are removed.

  * fixup! fix(release): wait for a CD run's attempt by reading it, not by gh run watch's exit status

  * fixup! fix(release): wait for a CD run's attempt by reading it, not by gh run watch's exit status

  * fix(cd): classify and back off a failed CD run read in finalize's wait and the develop-CD gate

  Move the classify-then-retry wait into lib/cd_runs as wait_attempt_completed, and route cd_runs.wait_completed and watch_run through it, so vrg-finalize-pr --wait-cd and vrg-release's develop-CD gate fail at once on a non-transient read error and report a persistent read failure as one, naming its cause, instead of as a run still in progress. Finalize reports it as CD: error (exit 1); the gate refuses as a read failure. The release's run_wait now wraps the shared wait. Ref #5174

  * fixup! fix(cd): classify and back off a failed CD run read in finalize's wait and the develop-CD gate
