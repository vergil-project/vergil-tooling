
# Release 2.1.310 (2026-11-14)

## Bug fixes

- **drop unused-allowed-license from the packaged deny.toml (#4368)**
Restore cargo-deny's default for allowed licenses a repo's dependency graph does not use: the warning shows again but does not fail the check. Ref #4354.

- **make the Pages step idempotent and report the create's HTTP status (#4373)**
A Pages create that landed was reported as a failure: GitHub answered it with an error status and an empty JSON-typed body, which gh reports only as 'unexpected end of JSON input'. Step 10 now reads the site first, POSTs once with -i so a failure carries its HTTP status, and on a failed POST re-reads the site: the requested source means the create landed (shown as a warning), another source or no site is a loud error. A re-run no longer repeats the POST into a 409.

## Documentation

- **document vrg-queue adhoc and name epic-review in the queue-item refusal (#4369)**
Adds vrg-queue adhoc to the github-issues queue view and ad-hoc epic passage, names the commands the queue-item refusal names, and notes vrg-queue adhoc as the collect step of epic-implement adhoc. Ref vergil-project/vergil-tooling#4366.


## Features

- **watch sync PRs until merged, updating a branch that falls behind develop (#4372)**
open_sync_pr no longer returns once auto-merge is on. It now waits until the PR has merged through pr_merge.wait_until_merged: a behind branch is updated, a ready PR is merged whether or not auto-merge is on, and a failed check, conflict, closed PR, the update cap of 5 or the deadline (VRG_MECHANIZED_PR_DEADLINE, 40 minutes by default) stops the wait naming the PR. The shared loop pieces of pr_merge are factored out so wait_and_merge keeps its behaviour. vrg-github-repo-config update exits 0 only once the sync PR merged and 2 when it did not.

Ref vergil-project/vergil-tooling#4370
