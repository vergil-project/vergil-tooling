
# Release 2.1.287 (2026-11-07)

## Bug fixes

- **quote the issue ref in the commands vrg-ruling prints (#3967)**
vrg-ruling draft and request's open-request refusal now print the issue ref single-quoted ('owner/repo#N'), so the pasted command works in zsh with EXTENDED_GLOB, where an unquoted # is a glob operator. The docs show the quoted form. Ref vergil-project/vergil-tooling#3962.

## Features

- **vrg-merge-review-check, the result check (#3981)**
Add lib/merge_review (the shared schema constants and parse_result) and vrg-merge-review-check, which checks a reviewer's stored reply against the request it answers by the nine rules of docs/specs/merge-review-protocol.md and exits 1 naming the rule broken, never the refused value. Ref #3940

- **vrg-change-class and the merge-review docs-paths key (#3993)**
Add classify, which calls a change docs-only or code from its changed files and an allow-list of base paths; the [merge-review] docs-paths key in vergil.toml; the merge_base and diff_name_status helpers in lib/git.py; and the vrg-change-class command for humans and debugging. Only additions and edits of allow-listed paths are docs-only; any deletion, rename, copy or type change, any vergil.toml change and an empty change are code. Ref #3941.

- **validate record and vrg-merge-review-request (#4005)**
vrg-validate now writes .vergil/vrg-validate-last.json after every pipeline
run (the commit at the start, exit code, whether the run was full and the
tree clean at the start, and each stage's status); run_pipeline gains a
results_sink for it.

vrg-merge-review-request builds a review or check request from a clean,
fully validated branch into build/.vergil-state/issue-implement/<N>/merge-review/
in the main clone, writing the request, the branch diff and a check's fix
diff, and refusing a stale, partial or failed validate run, a dirty tree,
unknown or unnamed finding IDs, and (exit 3) a rebased fix base. With
--ensure-dir it only checks the private directory and prints it.
ensure_build_dir and ensure_private_dir check build/ and each level below it
(a real directory, mode 700).

The change classifier, here and in vrg-change-class, reads the docs-paths
allow-list from vergil.toml as committed at the merge base rather than the
working tree. Adds the CLI Tools Overview entry.

Ref vergil-project/vergil-tooling#3942

- **refuse a --fix-base that is not the previous step's head (#4007)**
A check's --fix-base must equal the head_sha of the previous step's stored request-<step>.json, so the fix diff always starts where the judged change ended. Ref vergil-project/vergil-tooling#4006


## Refactoring

- **remove unused vrg commands (#3964)**
- **make wait_for_checks' required set mandatory and drop its self-lookup (#3970)**
Remove the _Resolve sentinel and the default that made wait_for_checks look up the base branch's required checks itself. Its only production caller, pr_merge, always resolves the set first and passes it through (None when the lookup failed), so the default path was reached only by tests. Tests that exercised other behaviour now pass required explicitly; the three that tested only the self-lookup are removed. required_check_names stays: pr_merge still calls it. Refs #3965

- **drop the standalone vrg-repo-profile command; vrg-validate runs the check (#3971)**
Remove the vrg-repo-profile console script. The check stays as bin/repo_profile.py (no command prefix, per the CLI entry-point standard), which validate_common runs in process. The docs describe it as a vrg-validate check. Ref vergil-project/vergil-tooling#3953.
