
# Release 2.1.290 (2026-11-08)

## Bug fixes

- **quote the issue ref in the paste-ready commands other tools print (#4052)**
Ref vergil-project/vergil-tooling#3966. The quoted_issue_ref helper moves from lib/rulings/draft_ref.py to a shared lib/shell_ref.py, with quoted_slug for an IssueRef. vrg-intake-create, vrg-issue-create and vrg-intake-route now print their vrg-epic-move and vrg-security-record retarget recovery commands with single-quoted refs, so a pasted command works in zsh with EXTENDED_GLOB. vrg-issue-create's command names the task in full instead of a bare #N, which would resolve against the cwd repo. The linkage-keyword refusal names the issue by number, with --repo for a cross-repo ref, since gh takes no owner/repo#N argument. The security-record docs show the quoted retarget form.

- **require the host settings.json on start, rebuild, session and cloud create (#4053)**
Every path that copies the guest Claude config now requires the host ~/.claude/settings.json, as vrg-vm update already did. copy_claude_config always checks the file and drops its require_settings flag, and start, rebuild, session and the cloud create and rebuild refuse a missing or invalid host file, naming it, before touching any VM. A missing file no longer leaves a stale guest copy for the plugin refresh to read. Ref vergil-project/vergil-tooling#3988.

- **post the check run in the PR's own repo (#4054)**
Resolve the repo from the PR itself with github.pr_repo_and_number (#4013's helper) instead of the cwd's remote, so a run from another repo's checkout posts vergil-audit/approved on the PR's repo. Ref #4033.

- **bound and check the gh list and search lookups (#4055)**
* fix(epics): bound and check the archive, reflink and normalize lookups

_open_standing_archive_rows and _reflink_child_states passed no --limit, so gh returned 30 rows; plan_normalize_adhoc passed 500 and never checked it. All three now ask for LISTING_LIMIT rows and raise EpicListTruncatedError through refuse_truncated when the result reaches it. Ref vergil-project/vergil-tooling#4038

* fix(epic-audit): bound and check the audit and roadmap searches and lists

task_drift saw 100 of the org's merged PRs (about 900 in the default 30-day window); it now searches the window a week at a time, each week held to search's 1000-result cap. closed_operational_without_success and epic_outside_dotgithub saw gh search's default 30; stray_dotgithub_issue and the roadmap's _open_epics never checked their limit. Each now refuses a result that reaches LISTING_LIMIT. Ref vergil-project/vergil-tooling#4038

* fix(release): refuse truncated release, deps and refresh lookups

find_existing_tracking_issue, _open_release_issues and find_open_fix_task relied on gh issue list's default 30 rows; pending_deps_prs and open_refresh_prs passed 100 and never checked it. Each now passes an explicit limit and raises its module's error when the result reaches it. Ref vergil-project/vergil-tooling#4038

- **bound and check the gh repo list lookups (#4059)**
list_org_repos and list_project_repos now pass LISTING_LIMIT and refuse a listing that reaches it via refuse_truncated, so neither acts on a possibly truncated repo list. list_project_repos filters in Python instead of --jq so the check sees every row. Ref #4051

- **name the created epic when the post-create lookup finds a duplicate (#4060)**
* fix(epics): name the created epic when the post-create lookup finds a duplicate

The title lookup now raises EpicTitleAmbiguousError (still a ValueError) carrying the matching refs. _await_listed turns it into StandingEpicDuplicateError, a StandingEpicNotVisibleError naming the epic this run created and the other same-titled epics, chained from the ambiguity. vrg-intake-route reports either post-create error as a clean refusal. Ref #3819.

* fix(epics): report an unconfirmed standing epic cleanly in vrg-epic-move and vrg-issue-create

Both commands caught only ValueError around resolve_epic_ref, so the post-create duplicate error, now a StandingEpicNotVisibleError, ended in a traceback. Merge review R1. Ref #3819.

- **report version-window errors with emit_error (#4061)**
* fix(repo-init): report version-window errors with emit_error

Steps 3 and 9 of vrg-github-repo-init raised SystemExit("error: ..."), which printed a lowercase line and skipped the ERROR: form and the GitHub Actions ::error annotation the other vrg-* commands give. Both now call emit_error and exit 1. Ref vergil-project/vergil-tooling#3978.

* style(repo-init): format the window-error test assertion

- **write every guest and generated file atomically instead of with cat > (#4062)**
* feat(vm): add a shared atomic file-write command for any path and mode

Generalises the copy_claude_config helper from #3987 into lib/atomic_write: the content goes to a temp file beside the target, gets its final mode there, and is renamed into place, so a failed write leaves the original whole. Adds a real-shell Transport double and a failing-command helper to the test conftest. Ref #4035.

* fix(vm): write every guest and generated file atomically instead of with cat >

Moves the guest credential, identity, token, trusted-authors, tooling-tag and dev-ref writes, the projected memory files, the apt pin and the package bootstrap source onto atomic_write_cmd, keeping each file's final mode. copy_claude_config now reads both host files and checks the settings before writing anything to the guest, so its docstring holds. Ref #4035.

- **point off-platform not-running hints at vrg-vm rebuild (#4067)**
vrg-vm start refuses every off-platform box, so the update and cp hints that named it led nowhere. They now name vrg-vm rebuild with the identity, which replaces the disposable VM and reattaches the persistent volume, and cp's missing-box hint names rebuild instead of a session that never creates a cloud box. The consuming-repo setup guide says the same. Ref vergil-project/vergil-tooling#3994

- **name a ruleset as the likely cause of a bare 422 on a REST refs write (#4069)**
GitHub's REST refs API answers a ruleset refusal with only 422 Reference update failed. GitHubAPIError now adds a note naming the likely ruleset refusal, the ref, the repo and how to see the rules; the error is still raised. Refs #3997.

- **allow deferring a planning issue whose development epics are all closed (#4001) (#4071)**
Defer now refuses only while a development epic of the planning issue is open: one an Epic: marker names (every marker, not only the latest), or one found by a limited, truncation-refusing search for its Planning: line. A failed or malformed lookup raises instead of assuming the epics are closed. Drop keeps its marker refusal.

- **read under the audited org's token and refuse a partial view as complete (#4072)**
* fix(epic-audit): read under the audited org's token and refuse a partial view as complete

- **open a PR only at the head the latest report-ready recorded (#4073)**
* fix(submit-pr): open a PR only at the head the latest report-ready recorded

vrg-submit-pr now refuses, with nothing pushed or opened, any submit whose head is not the recorded head_sha: a worktree HEAD that moved (template, batch before its rebase, named branch), a named branch reopened by unfreeze and not re-reported, a local state and relay ref that disagree, and an origin tip other than the expected head right before gh pr create. unfreeze now overwrites the relay ref with the reopened state first and fails with nothing changed if it cannot, so a stale ready relay ref can no longer survive an unfreeze. Ref vergil-project/vergil-tooling#3815

* fix(submit-pr): name unfreeze then report-ready as the recovery from a stale-head refusal

The freeze refuses a plain report-ready re-run on a moved HEAD, so the refusal now names the real recovery, including the batch item left rebased after a later failure. Per the human ruling on merge-review item R1. Ref vergil-project/vergil-tooling#3815

- **keep earlier failures when a later refresh listing raises (#4075)**
When claude plugin list --json or marketplace list --json raises after an add or update has already failed, refresh now raises a MarketplaceError naming the step's error and every earlier failure label, chained from the original exception. With no earlier failure the original exception propagates unchanged. Ref vergil-project/vergil-tooling#3989.

- **report settings the identity cannot read as not checked (#4076)**
* fix(github-repo-config): report settings the identity cannot read as not checked

Under the agent App every administration=read endpoint (vulnerability-alerts, actions/permissions, classic branch protection) answers 403, and the repo object omits security_and_analysis. The audit aborted on the first 403 with a raw header dump, read missing security_and_analysis as all disabled, and treated a classic-protection 403 as unprotected. Each unreadable setting is now recorded as not checked (needs administration=read), never compared, and never a clean result: audit exits 2 (1 if it also found drift), and apply refuses. A 403 that names no missing permission still raises, and error output drops the response headers. Ref #3816.

* test(github-repo-config): apply ruff format to the not-checked CLI test

- **name the created epic when a post-create lookup read fails (#4078)**
A read failure while _await_listed polls for a new standing epic now raises StandingEpicNotVisibleError naming the created epic, chained from the original error, and cli_main reports that error (and its duplicate subclass) as a clean one-line exit for every command that can create a standing epic. Ref #3820.

- **say in vrg-vm update output that it copies the host Claude config (#4079)**
The update already copies ~/.claude CLAUDE.md and settings.json before the plugin refresh (#3872), but printed nothing about it. Announce the copy so the human sees an update syncs the user config. Ref #3835.

- **rebuild step 3's answers from vergil.toml on a resumed init (#4080)**
A resumed fresh init skipped step 3 and rendered steps 4-10 from the context defaults (no language, a base container). It now reads step 3's answers back from the committed vergil.toml and re-resolves the versions, and stops loudly on a missing or invalid file, a contradicting flag, or a license or initial version it cannot recover. Ref vergil-project/vergil-tooling#3977.

- **refuse an unexpected response shape instead of reading it as empty (#4082)**
* fix(github): refuse an unexpected response shape instead of reading it as empty (#4058)

list_org_repos now raises the same TypeError list_project_repos raises for a non-list response, and refuses a row with no repo name. The sweep of lib/github.py makes graphql, the statusCheckRollup readers, run_completed, job_conclusion, pr_reviews, the PR-for-branch lookups and the required-check readers raise on a wrong-typed response too, keeping a genuinely absent field as empty.

* style(github): keep the PR-for-branch command within the line limit (#4058)

- **tell a stale branch from a workflow change on a workflow-permission push refusal (#4083)**
* fix(vrg-git): tell a stale branch from a workflow change on a workflow-permission push refusal

On GitHub's workflow-permission refusal, vrg-git push now checks the branch's own diff from its merge-base with the remote's default branch. A branch whose own commits change a workflow file keeps the report-ready hand-off; one whose own commits change none but whose base changed one since is reported stale, with rebase guidance, and the push keeps its failure code. When vrg-git cannot tell, it keeps the hand-off and says what to check. Ref #3814

* test(vrg-git): cover a failed diff in the workflow-refusal diagnosis

- **report unreadable queues and make the planning hold consistent with the spec (#4084)**
* fix(queue): report a queue that cannot be read instead of crashing (#3826)

vrg-queue now catches GitHub API, private-advisory-home and malformed-response errors from a view, names the queue and the reason on stderr and exits 1. A bare text run still lists the queues it read; a bare --json run prints no partial object. A missing token still reaches the guided message. The module docstring and the CLI reference now describe the advisory hold, its access needs and these failures.

* fix(queue): make the planning hold consistent with the spec (#3826)

Per the rulings on #3826: a planning item is held while any advisory tracks it, not only one its body names (spec 4.4b of vergil-project/.github#517); an item is a security item by its body line alone, and the queue_view docstring now says so; an advisory line naming an org other than the issue's own is refused, not ignored. Advisories are listed once per org; an org whose .github is absent or not public is skipped unless an item has an advisory line. The docs describe the same rule.

- **reject null, sourceless and repo-less github marketplace declarations (#4086)**
A null extraKnownMarketplaces entry, a null or missing source, a source with no repo, url or path, and a github source with no repo each raise a MarketplaceError naming the marketplace, instead of being read as empty or skipped and so silently neither added nor verified. Ref #3992.

- **tell a stale branch from a workflow change on report-ready's workflow-permission push refusal (#4087)**
Move vrg-git push's workflow-refusal diagnosis (#3814) into lib/git.py and use it from report-ready's _push_branch too. A branch whose own commits change .github/workflows/** keeps the hand-off (the state is recorded and the human's vrg-submit-pr pushes it); a stale branch whose own diff has none is refused with the rebase steps and nothing recorded; when the cause cannot be told, the hand-off stands with the same how-to-check note vrg-git prints. Ref #4077

- **install a user-scope copy of each user-enabled plugin even when a project-scope install exists (#4089)**
update_installed_plugins installed an enabled id only when it had no install at any scope, so a project-scope install made by Claude Code stood in for the user one. It now installs at user scope every id the user settings.json enables that has no user-scope install entry, per the ruling on #3836. Ref vergil-project/vergil-tooling#3836

- **keep the App JWT exp clear of GitHub's 10-minute ceiling (#4093)**
* fix(github): keep the App JWT exp clear of GitHub's 10-minute ceiling and name the rejected claim on a 401

The App JWT set exp to exactly now + 600, the most GitHub accepts by its own clock, so a local clock running even slightly fast made some mints fail with a bare 401. exp is now now + 540, matching the 60-second iat backdate. A JWT request rejected with an HTTP error now reports the endpoint and GitHub's JSON message, so the next failure says which claim or key GitHub refused. Ref #3825

* fix(github): report a truncated JWT error body as unreadable instead of letting it escape

http.client.IncompleteRead is not an OSError, so a cut-off 401 body escaped the AppAuthError wrapper. Ref #3825


## Documentation

- **name prod-base as the default no-language image in vrg-container-run's help (#4090)**
The docstring and --help said a repo with no language falls back to dev-base:latest. lib/container.py builds the fallback as <prefix>-base:latest with prefix prod by default, so it is prod-base:latest unless --prefix dev is passed. Ref #3833

- **say every repository gets the same four rulesets (#4097)**
The source-control standard said documentation repositories need only Branch protection and CI gates. compute_desired_state() has declared one uniform set for every repository since it was written (0b7ac4b50c), and a3984dd7dd removed the only per-repo exception, so the two-ruleset text, carried over in the standards migration (7bf36386ea), was out of date. The standard now says all four rulesets apply whatever the repository-type. Ref vergil-project/vergil-tooling#3979


## Features

- **add a claude-settings target for the managed .claude/settings.json (#4063)**
* feat(fleet-sync): add a claude-settings target for the managed .claude/settings.json

Add vrg-claude-settings-sync, a single-repo applicator that checks or atomically replaces .claude/settings.json with repo_init.render_claude_settings(), using the config audit's equal-after-parsing comparison so --check drifts exactly when --write changes the file. Register it as a console script and add a claude-settings target to vrg-fleet-sync, so a template change can be rolled out fleet-wide. Ref #4056

* fix(fleet-sync): use Path.replace for the atomic settings write and format the target test

- **support the global -C option, with every check and the token org following it (#4064)**
* feat(vrg-git): support the global -C option, with every check and the token org following it

vrg-git now accepts leading -C <path> options and changes into each (chained as in git) before any check runs, so the worktree convention, worktree add anchoring and lockstep, the issue lookup, protected-branch force, the freeze and the identity token's org all apply to the -C repo exactly as after a cd. The -C options are not forwarded, the previous cwd is restored on return, and every other global git option stays refused. Ref #3737

* test(vrg-git): type the -C test fixture's issue payload and format the token test

- **add --yes to vrg-promote and require a terminal only when prompting (#4065)**
* feat(promote): add --yes to vrg-promote and require a terminal only when prompting

With --yes, vrg-promote moves the rolling tag with no prompt and no terminal check. Without it, the move and the prompt go to stderr, and the command refuses unless stdin and stderr are both terminals, so a redirected stdout cannot hide the prompt. Ref vergil-project/vergil-tooling#3986.

* refactor(promote): keep main the first function in vrg_promote

- **close any closing-reference issue GitHub failed to auto-close (#4068)**
A new close-refs stage runs after the merge is confirmed. It reads the PR's closingIssuesReferences from GitHub (never parsed from the PR text), waits a short grace for an auto-close in flight, then closes each issue still open as completed with a comment naming the merged PR, and reports each one. A failed read or close fails the stage loudly after every close has been tried; cleanup still runs because the PR is already merged. Refs #4002.

- **turn off idle compaction in the managed settings template (#3795) (#4074)**
Add "idleCompaction": false to the packaged .claude/settings.json template and to vergil-tooling's own copy, with audit and repo-init tests, and document it. Context-full auto-compaction is left on.

- **add a claude-md target that syncs the CLAUDE.md template region (#4094)**
Add vrg-claude-md-sync, a single-repo applicator that checks or atomically replaces the region between the CLAUDE.md template markers with the packaged claude_md_consumer.md template, verbatim, leaving every byte outside the markers unchanged. It reuses the audit's marker parser and region comparison, now exposed from repo_config as claude_md_marker_lines and claude_md_region_divergence, so --check drifts exactly when --write changes the file. A missing CLAUDE.md or absent, malformed or duplicated markers is a named error (exit 2) in both modes, which vrg-fleet-sync records as that repo's error. Register it as a console script and add the claude-md target to vrg-fleet-sync. Ref #3868


## Refactoring

- **remove the uncalled _marketplace_sources and test the add list directly (#4066)**
refresh calls _marketplace_adds directly, so _marketplace_sources had no production caller. Its tests now assert the (name, add-arg) pairs _marketplace_adds returns, the list refresh runs. Ref vergil-project/vergil-tooling#3991

- **drop promote()'s unused dry_run; the CLI owns the dry run (#4081)**
- **share one poll loop between retry_known_resource and _await_listed (#4085)**
Add retry.poll_until, a predicate-based poll within a time budget using compute_delay's backoff with the last sleep clamped to the deadline, and build both retry_known_resource and epics._await_listed on it so a fix to the loop reaches both. Behaviour is unchanged, including #3820's read-failure handling. Ref #3821

- **share one GitHub remote URL parser between promote, detect_org and is_github_url (#4091)**
github_remote_repo in lib/github.py is now the one parser of github.com remote URLs: promote and detect_org read owner/repo through it, and is_github_url shares its host grammar (still matching any path on github.com, so has_github_remote fails closed). It never echoes the URL. Ref #3984.

- **read draft_ref push URLs and vrg-git clone URLs with the shared GitHub remote URL parser (#4095)**
Replace draft_ref's _GITHUB_REPO_URL_RE and vrg-git's _GITHUB_CLONE_URL_RE with github.github_remote_repo, so no GitHub remote URL regex remains outside lib/github.py. require_remote_is now also accepts git+ssh, ssh+git, user-less scp and leading-slash scp forms, and refuses a user part with '#', '?' or '\' that the old regex read as github.com. The vrg-git clone owner lookup now reads every form the shared parser accepts and no longer takes a URL whose path is more than owner/repo. Ref #4088

- **remove the vestigial vrg-trivy-scan command and lib/trivy.py (#4096)**
Nothing runs vrg-trivy-scan: the shared Trivy action and the container image scan call trivy directly. Remove the console script, its module, lib/trivy.py (imported only by it), their tests, and its entries in the CLI Tools Overview, the reference index and the CI architecture guide. lib/sarif.py and the SARIF commands stay. Ref #4092.
