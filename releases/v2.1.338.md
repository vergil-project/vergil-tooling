# Release 2.1.338 (2026-11-23)

## Bug fixes

- **hold back a ready worktree whose PR GitHub already has open or merged (#4993)**
  vrg-submit-pr --all and the root picker now ask GitHub for the branch's PR, since one opened by hand never stamps the state: an open PR is in flight, and one merged at the reported head is cleanup. A push refused because origin deleted the branch after its PR merged now says so, and vrg-repo-status no longer counts a branch that has a PR as prepared.
- **wait for a settled mergeable status before reporting a conflict (#4998)**
  Just after a push GitHub may still report the conflict the push resolved. vrg-finalize-pr now ends a PR failed: conflict only once the conflict has been reported at the same head for two minutes; until then the PR is pending, a new head starts the count again and any other merge state clears it.

## Features

- **print the vergil-tooling version in vrg-submit-pr and vrg-finalize-pr runs and logs (#4994)**
  Each run's first output line and its run log's first line now name the installed vergil-tooling version, so a validation can tie a host run to the release it validates.
- **refuse raw issue and PR content reads by agents (#5041)**
  * feat(hook): refuse raw content reads by agents in the hook guard

  * fix(hook): apply one rule to issue and PR lists and searches

  Per the merge-review ruling on R1: a list or search made only of qualifiers that requests no content field is allowed; one that matches text (a free-text term, an in: qualifier, --match, or a list's --search with text) or requests a content field is refused, naming vrg-issue-read. The tests render one table as lists and searches.
