
# Release 2.1.301 (2026-11-11)

## Bug fixes

- **print semgrep's error output when the scan fails (#4211)**
run_scan now returns semgrep's captured stdout and stderr. When semgrep exits above 1, vrg-semgrep-scan prints both before the error, and the error names the last non-empty stderr line (falling back to stdout), so a crash such as 'semgrep-core exited with -11!' reaches the CI log. The clean and findings paths are unchanged.

Ref vergil-project/vergil-tooling#4188

- **harden pasted commit text rendering and snippets config (#4212)**
* fix(release): neutralize line-start snippet markers in pasted commit text

The git-cliff changelog and release-notes templates now rewrite the first dash of any pasted line that starts with a MkDocs snippets marker as its HTML entity, so the text renders unchanged and is never treated as an extension directive. Ref #4182.

* fix(docs): confine pymdownx.snippets to the docs dir

The docs-site mkdocs.yml that repo init stamps, and this repo's own, now configure pymdownx.snippets restrictively: base_path is the docs dir, the base path is restricted, a missing snippet fails the build, and URL downloads stay off. Ref #4182.

* fix(release): treat a carriage return as a line start when neutralizing markers

Markdown reads a lone carriage return as a line break, so the templates' marker rewrite now uses the regex R flag to match after one as well. The test covers a subject and a body with such a line. Ref #4182.

* test(release): check a carriage-return subject only through the marker scan

git-cliff can drop a subject that holds a lone carriage return, so the test checks that case through the generic marker scan rather than an exact rendering. Ref #4182.

- **retry the base-image pull on transient registry failures before refusing (#4214)**
* fix(container): retry the base-image pull on transient registry failures

resolve_base_digest now makes up to three pulls, waiting 2 s then 5 s, when a pull times out or fails with a transient network, DNS, TLS-timeout or registry 5xx error. Definite answers (manifest unknown, not found, denied, unauthorized) and unrecognised errors still fail at once. The refusal names every attempt's error. Ref vergil-project/vergil-tooling#4210

* fix(container): retry transient DNS failures in the base-image pull

Classify Go's 'server misbehaving' (SERVFAIL) and glibc's 'temporary failure in name resolution' (EAI_AGAIN) as transient, alongside 'no such host', and state the hang bound in the retry constants' comment. Ref vergil-project/vergil-tooling#4210


## Refactoring

- **read published packages from one paginated release listing (#4213)**
The vrg-release preflight re-publish check now reads every packaged stable release and its asset names from collect.packaged_tags (one gh api --paginate --slurp listing) instead of one gh release list plus one gh release view per release. This drops the 1000-release listing limit. stable_tags, release_packages, _asset_names and RELEASE_LIST_LIMIT lost their last caller and are removed; the asset-name filter is now collect.package_names. Ref vergil-project/vergil-tooling#4205
